# 抖音千川钩子脚本Skill

## 1. Skill 基础信息

- Skill名称：抖音千川钩子脚本Skill
- Skill类型：生产型Skill
- 当前状态：启用
- 适用平台：抖音、千川投流、直播预热短视频、商品卡引流短视频
- 适用任务：抖音千川钩子脚本、短视频钩子脚本包、投流短视频脚本、短视频开头文案、短视频口播脚本
- 不适用任务：直接做资料调用、直接做合规终审、直接做直播整场话术、直接做公众号长文、直接做小红书图文笔记
- 最近更新日期：2026-04-28
- 维护说明：当平台规则、钩子资产库、框架编号体系、拍摄条件约束或客户禁用表达发生变化时，应同步更新本 Skill 的输入要求、路由规则、输出格式和引用边界

## 2. Skill 定位

本 Skill 是单客户专属新媒体工作台中的短视频脚本专项生产型 Skill。

它负责围绕抖音和千川投流场景，基于用户提供的产品、卖点、人群、痛点、拍摄条件和合规限制，输出可直接用于拍摄和投放测试的钩子方向与完整脚本包。

本 Skill 不负责做任务分流，不负责判断资料优先级，也不负责最终事实与合规放行。它应在“任务识别与调度Skill”和“资料调用Skill”之后使用，并在生成后进入“事实与合规检查Skill”。

## 3. 什么时候使用本 Skill

以下情况应优先调用本 Skill：

1. 用户要做抖音短视频或千川投流短视频脚本。
2. 用户要生成“钩子方向 + 完整脚本包”。
3. 用户明确要求写短视频开头、口播开头、短视频脚本、投流短视频素材。
4. 用户需要围绕一个核心卖点做 1 组或多组短视频测试脚本。
5. 用户已有对标内容、爆款开头或历史素材，需要路由出更适合当前产品的钩子脚本方案。

## 4. 什么时候不用本 Skill

以下情况不应使用本 Skill：

1. 用户只是要做资料筛选、资料优先级判断或资料充足度判断。
2. 用户只是要做事实核查、合规检查或平台风险检查。
3. 用户要的是公众号文章、小红书图文、私域群发文案或直播整场话术。
4. 用户只要求改一句文案，而不是生成整组钩子和脚本。
5. 用户没有短视频或投流场景，只是在做通用品牌说明。

8. 如涉及证明型脚本：实验、认证、产地、用户反馈的真实依据

## 6. 核心执行原则

1. 一条脚本只打一个第一卖点，不做卖点堆叠。
2. 钩子必须服务于停留、进入率和后续转化，不是单纯为了花哨。
3. 3-5 秒内必须给出人群、问题、冲突、结果或异常点之一。
4. 5-10 秒内必须落到第一卖点或第一痛点。
5. 没有证据的实验、认证、产地、评论、用户反馈、价格机制，不得写成确定事实。
6. 没有可拍摄条件时，不得硬写工厂、实测、产地探访或人物背书镜头。
7. 对标内容只能借结构、节奏、钩子形式和转折逻辑，不能迁移其中的品牌事实、数据、价格、承诺和完整句式。
8. 证据不足时必须降级表达，并在输出中明确假设与风险。

## 7. 执行流程

1. 读取任务单和资料调用结论。
2. 校验核心输入是否完整，按最小补问规则补足关键信息。
3. 判断脚本目标：拉停留、进直播间、转商品卡、测素材、快速转化，或其他投放目标。
4. 结合 `references/strategy-index.md` 选择 1-2 个策略族。
5. 结合 `references/hook-playbook.md` 选择主钩子类型。
6. 结合 `references/forms-and-visuals.md` 补齐形式、场景、动作和画面建议。
7. 如现有 `references/` 不足以覆盖当前产品场景，可补读 `02_资料库\短视频创作方法\全域素材破局\` 中的七大素材库、钩子类型和素材框架。
8. 基于一个第一卖点生成 5 个钩子方向。
9. 在方向中挑选最适合当前任务的 3 条完整脚本。
10. 输出假设、风险和需要补证据的点。
11. 将结果交给事实与合规检查Skill做正式检查。

## 10. 资产维护规则

1. 默认先新增案例，再决定是否升格为新框架。
2. 已有框架编号不重排、不覆盖原含义。
3. 新框架从 `F101` 往后追加。
4. 过时、高风险、平台不再适配的案例或框架应标记归档，而不是直接删除。
5. 维护时优先更新 `references/maintenance.md`、`references/cases/` 和相关框架说明，不直接破坏稳定路由规则。

## 11. 禁止事项

1. 禁止编造实验、认证、产地、用户反馈、价格机制。
2. 禁止把不可拍摄条件写成真实画面。
3. 禁止用对标案例事实替代客户事实。
4. 禁止在一条脚本里同时主打多个第一卖点。
5. 禁止为了投流效果而写高风险承诺、绝对化表达或虚假紧迫感。
6. 禁止在资料不足时写“真实体验”“真实结果”“真实测评”。
7. 禁止把本 Skill 当成事实与合规最终放行工具。

## 12. 与其他 Skill 的衔接规则

### 12.1 与任务识别与调度Skill

本 Skill 应接收以下输入：

- 目标平台
- 任务类型
- 内容目的
- 输出形式
- 建议输出路径

如任务未被识别为抖音 / 千川短视频相关任务，应先返回任务识别与调度Skill重新判断。

### 12.2 与资料调用Skill

本 Skill 只能基于资料调用Skill标记为以下类型的资料生成内容：

- 可作为事实引用
- 可作为结构 / 风格参考

标记为“需人工确认”或“禁止使用”的资料，不得写进正式脚本内容。

其中：

- `全域素材破局` 目录下资料默认属于“结构 / 风格参考”
- 不得把其中的人群、痛点、卖点、平台适配经验直接写成客户事实或平台规则
- `全域素材破局案例库` 目录下资料默认属于“结构 / 风格参考”；其中低风险案例可默认参考，高风险案例仅可条件式参考，且不可直接复用原案例事实和完整句式

### 12.3 与事实与合规检查Skill

本 Skill 生成的内容默认应进入事实与合规检查Skill。

尤其当内容涉及以下场景时，不得跳过检查：

1. 价格、优惠、赠品、库存、活动时间
2. 实验、认证、产地、工厂、用户反馈、效果证明
3. 健康、功效、食品、招商、收益、承诺
4. 对标仿写、爆款改写
5. 抖音 / 千川投流与强转化表达
