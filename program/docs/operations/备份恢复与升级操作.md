# 备份、恢复与升级操作

所有命令在包含 `package.json`、`setup-local.bat` 和 `stop-local.bat` 的程序目录执行：客户交付包为解压后的 `LimingZhiyao`，源码为 `program`。维护由主机管理员进行；通知同事暂停操作，等待任务结束或取消并释放资源，再运行此目录的 `stop-local.bat`。备份、恢复过程中不要启动网页、迁移工具或分析器。

## 需要保存的内容

| 范围 | 保存方式 | 恢复要求 |
| --- | --- | --- |
| D1 数据库、WAL 与本地持久状态 | `tools/backup-local.bat` 保存整个 `.wrangler/state`，包含隐藏文件 | 恢复完整状态，不单独复制一个 SQLite 文件 |
| MEDIA 与 MEDIA_LEGACY 的对象、元数据 | 同一状态 ZIP，包含两个 R2 桶的本地存储 | 数据库和附件必须来自同一备份点 |
| 密码摘要、公司/项目关系、版本、审核、发布、调用记录、数据库检查点 | 在 D1 中，随状态一起保存 | 正常启动会撤销旧会话；使用原账号密码重新登录 |
| `.dev.vars`、实际使用的 `.dev.vars.*` / `.env*`、主机 Cookie 文件 | 管理员单独保存到受控目录；不进入业务 ZIP | 配置和 Cookie 含密钥/登录凭证，不能提交 Git 或公开发送；系统/进程环境变量不随文件复制，需另行记录 |
| 程序、迁移、静态授权资料、套餐裁剪、交付凭证 | 保存对应版本的完整交付 ZIP 或源代码提交 | 客户版使用原套餐的程序，不能用开发版覆盖客户版 |
| Python 环境、Node 依赖、FFmpeg、语音/视觉模型缓存 | 可重建；安装器和下载步骤见交付说明 | 不把业务 ZIP 当成整机镜像；首次重建需要网络及足够空间 |
| `.local/analyzer-work`、日志、PID、端口记录 | 工作目录/运行记录，不在状态 ZIP | 排空任务后备份；恢复不要沿用旧 PID；必要时另外保存排障日志 |

状态包仍可能包含业务资料和网页上传的 Cookie 快照，应放在只有授权管理员可访问的位置。文件哈希用于检查完整性，不证明备份来源可信。

## 备份与配置保存

1. 停止服务后运行 `tools/backup-local.bat`，确认显示 `Backup completed`。新 ZIP 使用格式 2，清单记录文件路径、大小和 SHA-256；失败的 `.partial` 文件不会显示成成功备份。同一秒创建多个备份不会覆盖。
2. 单独保存配置。下面命令在当前安装内创建私密配置副本；之后将状态 ZIP、配置副本和对应程序包复制到受控的另一块磁盘，避免同盘故障全部丢失。

```powershell
$ErrorActionPreference = 'Stop'
$programRoot = (Get-Location).Path
$configCopy = Join-Path $programRoot ('backups/private-config-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '-' + [Guid]::NewGuid().ToString('N').Substring(0,8))
New-Item -ItemType Directory -Path $configCopy | Out-Null
$configs = @(Get-ChildItem -Force -File -LiteralPath $programRoot | Where-Object {
    ($_.Name -eq '.dev.vars' -or $_.Name -like '.dev.vars.*' -or $_.Name -eq '.env' -or $_.Name -like '.env.*') -and $_.Name -notlike '*.example'
})
foreach ($file in $configs) { Copy-Item -LiteralPath $file.FullName -Destination (Join-Path $configCopy $file.Name) }
$defaultCookie = Join-Path $programRoot '.local/douyin-cookies.txt'
if (Test-Path -LiteralPath $defaultCookie) {
    New-Item -ItemType Directory -Path (Join-Path $configCopy '.local') | Out-Null
    Copy-Item -LiteralPath $defaultCookie -Destination (Join-Path $configCopy '.local/douyin-cookies.txt')
}
Write-Host "Private configuration saved: $configCopy"
```

如果 `ANALYZER_YTDLP_COOKIE_FILE` 使用其他路径，另行复制实际文件并记录恢复位置；浏览器登录态不随此副本迁移，需要在目标电脑重新登录或导出 Cookie。不能把缺失的密钥、Cookie 或外部模型缓存标为已备份。

外部 Cookie 用明确路径另存，不读取或输出文件内容。例如在上面同一次 PowerShell 会话中执行（把两个路径改为实际受控位置）：

```powershell
$configuredCookieFile = 'C:\private\douyin-cookies.txt'
Copy-Item -LiteralPath $configuredCookieFile -Destination (Join-Path $configCopy 'configured-cookie.txt')
```

## 在隔离安装中演练恢复

1. 将同版本程序完整复制/解压到较短目录，例如 `C:\LimingRestore`，使用独立 `.wrangler/state`。关闭自动启动分析后台；先完成 `npm ci`。不要指向原安装的数据目录。
2. 将目标 ZIP 放入隔离安装的 `backups`。运行 `tools/restore-local.bat`，选择目标包。脚本先检查项目、格式、数据库条目、文件数量/大小/哈希和路径安全；随后在独立副本中检查 D1 / R2 的 SQLite 结构、非空表结构和外键关联，再要求输入 `RESTORE`。检查失败或取消时原状态不变。需要已安装的 Node.js 22.13 或更新版本；缺少运行时、空间不足或数据库异常时中止，不能绕过检查替换有效状态。
3. 配置另行恢复：先保存隔离安装已有配置，再复制私密配置中的实际配置文件和 Cookie；核对 `ANALYZER_BASE_URL`、Cookie/FFmpeg/缓存的路径及局域网设置。暂不发起付费请求。不同电脑的绝对路径需调整。
4. 正常启动，同事重新登录。检查公司/项目、成员范围、来源资料、稿件版本、原审核和发布记录、用量历史；在网页打开一份附件，确认其他公司账号不能读取。
5. 用明确标注的验收任务完成人工保存、提交审核、批准和发布登记；这一步登记测试记录，不能当作真实平台发布。模型生成、真实复盘和视频处理仍需要另外授权的真实素材与账号。
6. 记录备份文件、程序提交、恢复耗时、检查结果和限制。验证完成前不删除原安装或恢复前副本。

配置恢复也在停止服务后执行。下面代码在目标程序目录保存当前配置副本，再复制所选副本；若使用外部 Cookie，把 `configured-cookie.txt` 另行复制到目标主机受控位置，并修正配置中的路径。系统环境变量、FFmpeg 和模型缓存路径也需单独核对，不自动沿用旧电脑路径。

```powershell
$ErrorActionPreference = 'Stop'
$programRoot = (Get-Location).Path
$selectedConfigCopy = 'C:\private\private-config-已验证副本'
$previousConfigCopy = Join-Path $programRoot ('backups/config-before-restore-' + [Guid]::NewGuid().ToString('N').Substring(0,8))
New-Item -ItemType Directory -Path $previousConfigCopy | Out-Null
$configs = @(Get-ChildItem -Force -File -LiteralPath $selectedConfigCopy | Where-Object {
    ($_.Name -eq '.dev.vars' -or $_.Name -like '.dev.vars.*' -or $_.Name -eq '.env' -or $_.Name -like '.env.*') -and $_.Name -notlike '*.example'
})
foreach ($file in $configs) {
    $target = Join-Path $programRoot $file.Name
    if (Test-Path -LiteralPath $target) { Copy-Item -LiteralPath $target -Destination (Join-Path $previousConfigCopy $file.Name) }
    Copy-Item -LiteralPath $file.FullName -Destination $target
}
$savedCookie = Join-Path $selectedConfigCopy '.local/douyin-cookies.txt'
if (Test-Path -LiteralPath $savedCookie) {
    $targetCookie = Join-Path $programRoot '.local/douyin-cookies.txt'
    if (Test-Path -LiteralPath $targetCookie) {
        New-Item -ItemType Directory -Path (Join-Path $previousConfigCopy '.local') | Out-Null
        Copy-Item -LiteralPath $targetCookie -Destination (Join-Path $previousConfigCopy '.local/douyin-cookies.txt')
    }
    New-Item -ItemType Directory -Force -Path (Join-Path $programRoot '.local') | Out-Null
    Copy-Item -LiteralPath $savedCookie -Destination $targetCookie
}
Write-Host "Previous configuration retained: $previousConfigCopy"
```

以上配置复制不是原子事务，复制中遇到磁盘/权限错误会停止，但先前文件可能已复制。不要启动服务；保留已保存的旧文件并逐项核对，从 `config-before-restore-*` 恢复受影响配置后再重试。命令只覆盖副本中明确存在的文件，不自动删除目标安装的其他配置文件。

数据库检查使用 `.wrangler` 内短目录中的数据库副本，包含对应 WAL/SHM/journal，不会为检查而回写被解压或当前状态。恢复所需空间应容纳解压状态和数据库检查副本。结构检查不是业务验收、来源可信性或所有程序版本兼容性的证明；仍需第 4、5 步检查实际登录、附件和关联。

旧格式 1 没有文件哈希，默认拒绝。先在隔离安装检查数据和附件，再显式运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/restore-local.ps1 -BackupPath 'backups/旧备份.zip' -AllowLegacyBackup
```

兼容恢复仍要求输入 `RESTORE`；显示警告表示完整性证据不足，不能声称哈希校验通过。可在验证后重新创建格式 2 备份。

## 正式恢复和回退

正式恢复先保护备份点之后的新资料，再停止服务、恢复状态、核对配置并启动。脚本使用同卷暂存和目录改名，保留 `.wrangler/state-before-restore-*`；最终替换失败会尝试恢复原状态。磁盘/权限故障造成回退也失败时保留目录供管理员排障，不自动删除任何业务副本。

恢复后若业务核对失败：停止服务，把当前 `state` 改名保存，再把选定的 `state-before-restore-*` 改名为 `state`，使用对应程序版本重新启动。路径须明确属于目标安装，禁止删除目录后再找回退副本。

## 安装、升级与故障验收

0051 为额度检查和索引的增量迁移，不改写已有业务行或公司额度。升级前保存状态、配置及对应程序，先在隔离安装执行迁移；已有用量超过新额度时仍保留，新增任务/附件会拒绝。新任务接收时间为数据库 UTC 时间；旧任务时间不重写，导入完成结果不占新分析额度。

额度按有效媒体记录统计，包含分析产物；备份、未关联对象、历史对象及工作缓存属于另外的磁盘用量。存储满导致产物失败时，先核对已保存附件和检查点，再处理容量并继续；错误码 STORAGE_QUOTA_EXCEEDED 与供应商模型限流不同，不自动替用户清理或重新派发模型。缺公司额度行的旧库使用数据库原默认上限（500 次/20 GiB）；公共提交预检会初始化设置，客户模式按套餐覆盖对应上限，不能把默认值当作客户套餐授权。

### 迁移失败后回退

迁移文件逐条执行，后面的文件失败时，前面成功的文件可能已经提交。看到失败提示后不要继续启动旧程序、反复重跑迁移或手工删表；迁移退出非零不表示数据库回到了升级前。

1. 升级前停止服务，保存业务状态 ZIP、私密配置和对应的完整程序包；在隔离安装确认能恢复。记录三个副本的路径、套餐和程序版本，保留升级前安装。
2. 迁移失败后保持服务停止，保留失败日志与当前整个安装，尤其是数据库、迁移文件和升级后新增资料。需要排障时运行备份保存当前状态，但该档案不是已验证可用的恢复点。
3. 在独立短路径目录解压升级前的同套餐完整程序包，安装其锁定依赖；复制升级前私密配置，并按本说明调整路径。不要只替换几个脚本，也不要在升级后的库上直接启动旧程序。
4. 在这个隔离目录恢复升级前已经验证的业务状态 ZIP，确认数据库检查通过。运行旧程序配套的安装/启动入口，重新登录；检查资料、附件、版本、审核和发布关联，并完成一项明确标记的人工保存/审核操作。
5. 核对备份点后是否新增业务，先保护这些记录再安排恢复；恢复旧状态会撤回备份点之后的数据。隔离回退确认成功后，由管理员在服务停止时切换安装目录，并重新核对地址与同事登录。保留失败安装和所有副本，不自动合并或删除数据。

只有在隔离环境证明旧代码与升级后的结构/数据兼容时，才可以保留当前库直接退程序。正常迁移成功、部分失败、恢复和回退都需记录退出码与业务核对结果。源码交付验收会注入两条合成迁移，验证一条提交后下一条失败，再恢复程序/配置/状态及重新登录读写；它不代替实际两个发行版本之间的兼容验收。

- 新电脑：按交付说明解压到短路径，运行 `setup-local.bat`；缺 Node、网络失败、依赖被安全软件隔离时应明确失败，不能继续宣称安装成功。分析器另运行 `tools/setup-analyzer.bat`。记录电脑/系统、运行时版本、安装耗时和下载失败提示。
- 升级：保存状态、配置和旧程序版本；先在隔离副本替换程序、执行 `npm ci` 和 `npm run db:local:migrate`，检查旧业务数据与附件，再做正式升级。不能用空库或开发配置覆盖现有安装。
- 重启：检查原数据持久化、旧会话失效、重新登录和分析队列恢复；操作系统实际重启及多机连接需在目标设备验证。
- 启动准备：数据库迁移完成后，在网页/数据库写入互斥下把上次未完成的网页任务标记为 `WEB_PROCESS_INTERRUPTED`。它保留模型调用额度、收到的用量、原稿和记忆来源，不自动发起模型。重新登录后核对改写失败记录、商品运行、记忆事件和助理失败回复，再按需重试；缺少最终回执的旧请求可能已经计费。该步骤不改变分析器自身的租约和恢复规则。
- 回退：按上面的“迁移失败后回退”步骤恢复匹配的程序、状态和配置；只退程序保留新增表须先验证兼容，先保护备份点之后的数据。
- 官方本地/LAN 启动、安装、备份、恢复和出厂重置共用互斥保护；`npm run db:local:migrate` 也会拒绝与维护或其他迁移同时运行。重复打开已有网页不会重新撤销会话。不要绕过启动器或用原生 Wrangler/SQLite 命令修改正在维护的状态；这些直接工具不受入口锁统一控制。

恢复出厂设置重建失败时，原数据库、Cookie、日志和配置保持；成功后旧库位于 `.wrangler/state-before-factory-reset-*`，Cookie/日志等位于 `backups/private-reset-*`，其中含私密登录资料。新库或运行文件整理失败时会执行回退，失败新库保留为排障证据。运行文件副本也需要由授权管理员保管，不能公开发送。

### 上传结果不确定或暂存附件清理失败

数据库提交回执丢失时，服务会查询附件、视频和任务关联；确认已入库则返回已提交，结果无法查询时保留附件并提示待核对。不能把错误提示当作数据库没有写入，更不能直接删除同名文件或整个附件目录。

1. 用户记录时间、公司/项目、文件名及提示，先刷新分析列表核对；待核对项确认前不重复上传整批。登录/权限、配额、网络或清理异常导致暂停时，剩余文件尚未尝试。
2. 管理员先等待已开始的任务结束或取消并释放资源，停止服务，保存当前整个状态 ZIP 和对应程序/配置。状态备份包含已关联附件，也包含可能遗留的未关联对象。
3. 在隔离副本核对媒体记录、视频、分析任务和对象的键、大小/哈希及归属，确认关联存在的对象必须保留。数据库暂不可读时先处理服务故障，不靠“文件旧”“文件名相同”判断可以删除。
4. 已确认没有业务关联的暂存对象仍需单独排障处理；当前系统没有自动孤立对象扫描/删除工具，不能宣称清理已完成。现有素材修复只处理关键帧/字幕的历史桶复制，不能用于清理原始上传对象。保留备份和排障记录后，再由维护者针对明确对象处理。

本说明不要求公开发送业务附件、数据库或配置；脱敏的错误提示、时间和文件信息足以开始排障。上传中的事务故障测试仅验证合成存储，真实磁盘断电和对象存储长期不可用仍需目标环境验收。

## 维护者可复执行的自动化证据（仅源码）

媒体入库两个入口增加独立读取保护：上传解析上限为 50 MiB 文件加 64 KiB 表单开销，仍按文件自身大小拒绝多一个字节的文件；链接 JSON 总 UTF-8 上限为 32 KiB。声明长度仅用于提前拒绝，较小或缺失的长度不能绕过实际字节检查，JSON 结构/字段类型及畸形上传返回 400。

超限时不把超额数据交给解析器，会在最多额外 64 KiB 和一秒的窗口内丢弃剩余流；声明超限时整个丢弃前缀最多为解析上限加 64 KiB。底层每次 read 已交付的当前块也计入原始读取，不能把这个数值当作进程内存上限。有限丢弃用于让接近上限及分块请求得到 413；严重超限或不继续发送时会终止流，部分客户端可能只看到连接中断。没有无限 drain、自动重新提交或模型调用。有效请求的完整上传总时限和全局并发内存限制尚未在此保护中实现。

下面的资源快照仅统计隔离 Node 及其子进程，排除采样器和子进程；每进程峰值/CPU 为从进程启动以来累计，包含初始化及前序场景。工作集存在共享页，不得相加称为独占物理内存，也不能用合成大文件测试推算真实多机容量。

下列命令供维护者在源码 `program` 目录运行；测试与内部验收脚本不随客户包交付。客户安装使用上面的隔离恢复演练步骤，不运行这些测试命令。

```powershell
node --test tests/local-backup-runtime.test.mjs tests/local-delivery.test.mjs tests/commercial-delivery.test.mjs tests/operations-stage-six.test.mjs
$env:LAN_TEST_BACKUP = '1'
$env:LAN_TEST_ROUNDS = '1'
$env:LAN_TEST_RESOURCE_SCRIPT = Join-Path (Get-Location).Path 'scripts/test-runtime-resources.ps1'
node scripts/test-lan-runtime.mjs
Remove-Item Env:LAN_TEST_BACKUP, Env:LAN_TEST_ROUNDS, Env:LAN_TEST_RESOURCE_SCRIPT
```

## 升级后核对素材操作

工作簿的 workbookPr/date1904 控制 XLSX「发布时间」数值日期转换；true/1 使用 1904，false/0 或省略使用 1900，重复/非法属性拒绝。其他数值列、品牌知识中的数字以及文字单元格不因该属性改变。CSV 的数值日期无工作簿属性，默认 1900；1904 导出的数值 CSV 请优先使用原 XLSX，不能猜测日期系统。1900 的序列号 60 是不存在的 1900-02-29，会明确拒绝。

非法年月日/时分秒/时区、含糊短年与日/月顺序不自动纠正；需要修改文件再预检。计数项的整数与安全精度先检查，完整行再使用服务端同一字段规则核对必填、长度、整数范围、链接等；错误整次拒绝预览，不四舍五入或让超范围数据先提交。XLSX 同样必须有作品名称/发布时间/播放量表头，不能缺列后全当作零。错误提示使用数据序号，不保证对应含空行/多行单元格文件中的物理行号。

没有数据库迁移或批量改历史时间。旧文字时间曾采用浏览器当地时区，重试时选择与旧电脑一致的选项；修正 1904、无效日期或改变时区会改变关联与导入摘要，重导前先核对旧作品/快照，不自动合并、删除或覆盖。完整 API 直接导入偏移字符串、历史混合时区的排序/去重和其他供应商日期/样式仍需单独审查，不能将本次客户端规范化当成服务端所有时间数据已清理。

### 服务端实际时刻与历史重复快照（2026-10-13）

两种复盘导入在服务器规范化实际时刻，保留输入小数秒精度，统一新记录和新摘要的 UTC 表示。等价偏移/零小数写法不能借另一字符串新增同一作品、同一时刻的快照；事务内检查已有实际时刻，计数来自真正保存记录。使用原始解析摘要同时查找旧批次，原文件的 failed 重试仍保留旧快照与源摘要。历史变更表示方式可能形成接受 0 的跳过批次，不宣称所有历史摘要自动迁移；旧失败批次仍优先使用原文件核对重试。

读取复盘时在查询/内存视图按实际 UTC 时刻筛选、排序和分组，保留存储原文。小数秒先拆分、整秒做偏移转换，再保留原数字比较，不让 SQLite 毫秒舍入把更细时间并在一起。员工结果只取周期末之前的 completed 批次快照，每作品一项；失败/processing/未来快照不作为当前周期成果，内容关联同时核对公司和空间。

历史同一时刻多条快照使用先入库记录（同入库时间按 ID 稳定排序），避免重复计算，概览/新生成企业报告显示重复与冲突数量，员工报告注明最新时刻重复需核对。首个值不代表已经证明正确；不合并或删除冲突数据，不改冻结报告，不替管理员做历史取舍。备份恢复仍保留全部原 ID、时间文本、批次、审计和关联，无新迁移。实际大库计算成本和历史异常时间格式仍须单独验收。
