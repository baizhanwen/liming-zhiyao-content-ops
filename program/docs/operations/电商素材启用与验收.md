# 电商素材启用与验收

更新日期：2026-09-13。适用范围：电商素材 v0.1，迁移 `0048_ecommerce_foundation.sql`，提示词 `ecommerce-content.v2`。

技术实现与合成链路已完成；真实商品试点尚未验收。当前本地业务实例已经执行增量迁移，电商仍在所有空间默认关闭。这里的测试结果不表示已经发布电商视频或验证成交效果。

## 启用条件与操作

1. 确认安装版本包含迁移 0048。其他安装必须先停止应用与分析后台，备份状态和配置，在副本验证升级及恢复，再运行 `npm run db:local:migrate`。不要把本机已经升级理解为其他安装也已升级。
2. 公司管理员从内容生产的「电商素材设置」进入，或直接打开 `/content/ecommerce`，选定公司和空间，在「空间设置」开启。默认关闭时员工不显示电商入口，管理员保留设置入口；开启后显示「电商素材」。
3. 设置空间并发数和月调用上限。电商调用同时计入公司额度，每次运行最多五次模型调用；取消不会取消已经发生的费用。先只启用一个试点空间。
4. 准备商品、证据和方法，按[使用说明](../电商素材使用说明.md)确认资料、创建任务、核对生成依据、人工审核、登记作品、回填结果。
5. 只有真实试点通过，才扩大启用范围。未完成的业务验收应保留负责人、来源与缺项，不能用合成测试稿代替。

当前自有账号登记支持抖音元数据，未接平台授权或自动发布。统一审核中心、订单物流、自动投流、跨空间商品共享与趋势预测均不属于本版。

## 本机升级及回退

迁移前已停止本机应用与分析后台。状态备份位于 `backups/liming-zhiyao-20260913-200714.zip`，配置另存于同目录的 `liming-zhiyao-20260913-200714-config/`，其中包含私密配置，只在受控本机保存。常规状态备份脚本不包含模型密钥，不能遗漏单独的配置备份。

副本恢复了 459 个状态文件，执行实际 Wrangler 迁移后，65 张旧业务表的逐行内容哈希和表结构保持一致，新增 13 张空电商表；原备份再次恢复得到迁移前数据。SQLite 临时共享内存索引允许因只读检查变化，持久数据库、WAL 与媒体另行比对。D1 自身执行计数和迁移记录的预期变化不当作业务数据变化。

正式实例迁移后再次核对：65 张旧业务表、449 个媒体相关文件与本地配置保持一致，数据库完整性检查通过。网页与分析后台已恢复；原工作区接口只读检查通过，启用电商的空间数为 0。

`node scripts/verify-ecommerce-upgrade.mjs <备份路径>` 只适用于仍处于迁移前、已停止服务的安装，读取原数据并在恢复副本迁移。当前本机已经升级，不应直接重复执行该前置演练命令。

异常时先由管理员关闭当前空间电商功能，历史仍可读，停止新生成和写入；已有运行可取消或按恢复规则处理。若需退回旧应用代码，保留新增表，不删除电商数据。只有数据库本身需要恢复时才考虑整库恢复，并先保护备份点之后新增的普通业务与电商资料。

恢复前停止服务，确认目标安装和备份来源，再执行 `scripts/restore-local.ps1` 并按提示选择备份、输入 `RESTORE`。脚本保留恢复前状态。不要把旧备份直接覆盖正在运行的数据库，也不要用空状态目录替换现有数据。

## 尚未完成的真实业务验收

以下依赖企业提供资料，均保持待验收；负责人由企业指定。建议首个组合为「抖音自然流 → 商品点击」。

| 待验收项 | 需要的真实资料与通过条件 |
| --- | --- |
| 真实 SKU 和可证明卖点 | 有商品及后台权限；确认规格、主张、证据、允许表述、有效期与禁区；内部字段不出现在公开输入和稿件 |
| 实际方法和案例适配 | 企业确认资料授权与来源；按真实商品、受众、购买障碍及拍摄条件核对选择理由；老板所述飞书全目录尚未连接或导入 |
| 拍摄与审核 | 逐段确认口播、画面、证据演示和 CTA 可执行；解决全部待确认事项；独立人工审核指定版本 |
| 实际作品与后台结果 | 人工发布后登记真实作品、账号和版本；依据后台回填观察时间、归因口径及已取得的点击/成交/退款数据，缺项保持未填 |
| 业务追溯 | 从真实结果回到发布版本、商品事实与采用方法；修正数据保留历史，不把播放表现解释成成交有效 |
| 其他平台、目标和投流场景 | 分别验证目标、承接、拍摄与指标口径；表单允许填写不代表已验证适配 |
| 客户现场环境 | 实际多机局域网、真实视频分析与客户部署条件另行验证；同机自动化结果不替代现场验收 |

真实结果不会自动升级为通用方法或品牌知识；需要人工评估证据质量与适用条件。未来趋势观察方案继续保留在设计目录，电商实施临时方案在技术收尾后删除。
