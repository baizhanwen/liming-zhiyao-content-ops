# 视频分析 v12：逐段核对与可用结果

## 问题与行为

旧流程中，一句口播校正不能由画面文字确认，就会阻止所有内容模块；视觉分析也受影响。重复生成完整稿件无法补足原本缺少的证据，重试耗时和费用却增加。

v12 将任务执行、报告可用性和稿件核对分开。分析仍展示四个内容模块及65维分类；可靠证据足够时正常完成。个别句子有疑义时，完整稿件保留原始转写并标出时间，候选改写单独展示。缺少证据的分类保留“无法判断”，不会变成“没有该特征”。

## 开发约束

1. 口播仅返回局部改动。普通中文校对可由同音、近音和语法语境支持，限制为累计1–3个汉字等长替换及至少85%原字保留；不得借此改数字、单位、币种、版本、专名、主体、否定或事实方向。字幕路径按真实局部短行验证，允许审计式修正错误引用；不将整屏平均置信度当作字幕字级置信度。一个改动被拒绝只影响所属片段。保留全部原始编号和时间；待核对槽位不进入分析证据。
2. 每批最多两次付费调用，输出截断补救和定向校正共享额度。截断时增加输出上限；不能确定时保留待核对状态；没有新信息的uncertain不自动重复付费询问。重试仅处理指定疑义句，成功内容和原片取证通过校验后复用。
3. 画面独立分析。文字模块只使用已核对片段；原始开头或结尾有缺口时不得跨过缺口拼成首句、行动引导或逐字引文。综合模块仅引用已验证上游结果。
4. 开头画面和真实首帧优先进入模型。密集界面OCR仅截取连续短摘录供本次模型输入，原始证据仍保留；抽样或待核对缺口不能支持全片未出现的断言。
5. UI 分别显示报告完成状态与口播待核对数量，保留按句补充、原片定位、人工校正、复制与导出。复制和导出保留待核对原文及时间标记，不采用候选。下游选题、知识、记忆和改写只接收已验证结果和文案。
6. OCR保留原模型、分辨率和帧，识别批量由6改为1；固定两张密集文字画面正向、反向对照全文一致且约快34%。仅对显式支持的本地OCR适配器缓存同任务内SHA256完全相同的图像文件；近似画面不复用。真实视频仍保留87帧，OCR由约474秒降到310秒，约快35%；这不等于全流程快35%。
7. 新默认 `analysis.v12 / unified-report.v2 / canonical-transcript.v2`；v11历史保持原有读取方式，不迁移业务数据。保持唯一完整开发版，不新增听觉分析。

## 验收

离线回归覆盖疑义片段隔离、稳定编号、首句缺口、行动引导跨缺口、全稿缺失时视觉独立、定向重试、输出上限、缓存、复制与下游安全。真实验收使用用户最新失败视频和当前配置的 MiniMax-M3.1-Flash；真实材料仅保存在本地私有验证目录。本轮按用户最新要求只完成本地开发、实测和界面验收，不推送GitHub、不发布安装包。
