# 视频分析 v10 开发方案

本方案以 `deliverables/短视频运营分析框架.md` 为分类依据。范围为硬指标、视觉、文案八维度、综合分析、跨视频内容对比及结果呈现；本轮保留语音转写，增加基于转写的字数和估算语速，不新增音乐、音效、音色情绪、音量、静音或节拍分析。此前暂缓的电商问题不在本轮范围。

## 交付目标

新版默认生成 `analysis.v10`。保留当前摘要、钩子、结构、受众、专项诊断、CTA 和校正口播稿等字段，以保持选题、素材、改写和历史报告兼容；另增加统一的 `content_analysis`，作为分类展示与批量统计的数据来源。已有报告保留原样，不从旧版散文猜标签，不自动重跑或调用模型。

分类、测量和解释分别记录。代码负责数值、去重、次数和比例；模型负责有证据的分类、信息单元和解释。识别出的信息点数量是模型分类结果的代码计数，不是客观真值。模型评价不能变成真实传播、完播或成交效果。

## 数据契约

单一标签库位于 `services/analyzer/liming_analyzer/resources/video-taxonomy.v1.json`，供 Python、服务端和页面共同使用。保存固定标签 ID、中文名、单选/多选、主标签要求、材料要求和版本。声音刺激等本轮排除的类型禁止输出；不因标签中文名变化改变 ID。

`report.content_analysis` 的顶层为：

```text
schema_version: content-analysis.v1
taxonomy_version: video-taxonomy.v1
profile: standard | max
evidence_registry: 原始转写、OCR、视觉观察、帧和有序帧组的证据定位
classifications: 按维度保存统一分类结果
segments: 带时间范围和角色的结构段落
information_units: 带证据的信息点、步骤、案例与重复表达单元
metrics: media / shot_detection / transcript_statistics / methodology
module_status: 各分类模块取得结果或失败的状态与原因
validation: passed / issues
```

每个分类结果包含 `dimension_id`、`state`、`tags`、`primary_tag`、`reason`、`evidence_ids`。状态固定为 `known`、`unknown`、`not_acquired`、`not_applicable`；确认没有用已定义的无特征标签或 `known + []`，其他状态不伪造为零或无。需要主标签时，主标签必须属于已选标签。

证据只能引用真实取得的原文、时间和帧。人工转写来源单独标记。只具有句级时间戳时，不生成伪精确的前 3 秒逐字截断；保存重叠片段及其实际时间精度。人物身份、受众、意图唤起的情绪等推断必须说明依据与不确定性。

## 处理流程

1. 沿用本安装独立的原片获取、媒体校验、ASR、OCR 与视觉模型。
2. 读取显示方向、像素比例、时长和画幅；计算时长桶、检测切换边界、段长、平均段长和每分钟检测切换数。保留算法与阈值，不把场景检测结果称为无误差的剪辑次数。
3. 使用纠错前转写计算统一口径的有效字符数、全片平均字符速度及可靠时间段的字符速度。时间异常时标记不可计算；不由转写间隔推断静音、人声覆盖或真实发声时长。
4. 首个可解码帧和前 3 秒密集取样独立标记角色；黑场、重复画面同样保留。强制证据不被普通相似过滤、低对比过滤、帧数裁剪或文本选样删除。
5. 保留正文代表帧，并在有界的场景切换窗口生成有时间顺序的帧组，供运动、稳定性及转场判断。缺少连续证据时明确无法判断；数字缩放与实际推镜等含混情况不强制分类。
6. 分模块生成统一分类：选题/Hook/结构/人群，情绪/价值/话术/语言，视觉，综合配合。每个模块设独立上下文与输出预算，校验标签、状态和证据；失败保存原因，避免单个超长 JSON 截断整个报告。
7. 保留现有文字诊断和 AI 原稿纠错；结构化分类与诊断共同通过质量验收后，才能作为已验收的新版报告使用。

视觉分类覆盖首帧样式和信息、前 3 秒、表现形式、场景、人物、辅助画面、文字类型、景别、构图、角度、色彩质感以及有时序依据的运动、稳定性和转场。只有保留检测框或实际识别结果才能输出抽样文字面积等测量，不承诺精确的整片真人出镜占比或字幕遮挡百分比。

## 页面与批量对比

详情页保留原有文字报告，增加硬指标、开头专项、分类分组、段落/信息单元及证据查看。显示分类状态和材料缺失原因；字幕与原版口播继续独立保存。Markdown 导出包含新版分类与口径，不能把 JSON 直接堆给用户。

素材中心和对标库增加“内容对比”，对用户明确选择的 2–100 条素材计算，不把前端最多 300 条列表误当全库。服务端复用当前公司与项目权限，按视频去重，每个视频固定一个已验收的新版报告，并返回分析 ID 与版本快照。

统计口径：

- 主类型占比：某主类型的视频数 / 当前字段 `known` 视频数。
- 多标签出现率：含该标签的去重视频数 / 当前字段 `known` 视频数；合计可以超过 100%。
- 同时显示未知、未获取、不适用数量和有效样本数。
- CTA 的视频占比、事件次数、位置分别统计；信息单元数量保留识别方法说明。
- 不同标签版本、测量版本和采样策略分组，不能静默混算。
- 旧报告、未验收报告及缺失数据单独计数；不借助模型直接编造百分比。

对比页面提供逐视频矩阵、分类分布、有效样本覆盖、可比硬指标及 CTA/信息单元概览，支持按内容形式、选题类别和时长桶筛选，并导出统计快照。

## 兼容与质量

集中定义契约识别和质量判定，修正当前仅对 v7 执行质量门的接点；完成接口、详情、列表和迁入状态共用规则。新版材料缺失或关键校验失败保留报告并说明，不能因为 JSON 可解析就显示完整成功。未经验收的新版不进入新知识原子和对标记忆。

新版本继续保留旧文字字段与完整稿来源，不覆盖原分析、原子、历史引用或私密配置。旧分段检查点仅在契约/提示词/标签版本兼容时复用分类；原始媒体与证据检查点可以继续复用。迁移包保留完整 JSON 和质量状态，导入不触发模型调用。

## 实施与验收顺序

1. 固定标签库、数据契约和纯函数校验，补兼容读取与质量判定。
2. 完成代码指标、强制开头取证、视觉时序证据与分类子任务，接入默认 v10 生成。
3. 完成详情展示、导出、服务端聚合与内容对比页面，验证权限和统计分母。
4. 运行有意义的单元与集成回归：时长桶边界、旋转/SAR、无音轨/无视频轨、黑首帧、开头重复、短于 3 秒、快切/闪光、异常转写时间、视觉失败、非法标签、越界时间、无效证据、截断输出、旧报告/迁移往返、跨公司和项目访问、同视频多分析与不同版本分组。
5. 完整构建、必要全量回归、真实 Windows 环境与独立交付包验收通过后，更新 GitHub 源码和 Windows 下载包；本机空闲时重启并检查新版。

合成测试证明流程、约束与计算口径；模型分类准确性仍需带人工标注的真实样本校准。首次 50 条可作为抽检批次，不预先宣称准确率或真实运营效果。
