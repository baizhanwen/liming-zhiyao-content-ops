# 视频分析 v11 修复与验收方案

本轮依据用户对真实视频测试的反馈，统一分析流程和报告页面。先完成本机真实样本验收，再提交 GitHub 与发布唯一完整开发版。旧数据和分析版本保留，旧报告不自动重跑，不新增听觉分析或电商功能。

## 已确认的问题

约115秒的视频耗时12分48秒；82帧分14批串行视觉请求，正文、专项报告、校正和新增分类又串行生成。四个分类模块的7次请求全部失败；页面仍铺出65张未知分类卡和15块旧诊断。转写校正未利用已有画面文字，数字版本改错仍通过忠实度检查；后续诊断使用另一份未校正文案。任务只保存证据检查点，失败后不能只补某个分类模块。

## 流程

1. 保留原始ASR、OCR与画面，生成可追溯校正文案。逐段映射和时间精度不变，OCR只作有依据的校正参考；专名、数字、型号和版本不得按模型常识擅改，冲突保留复核状态。无证据的中文小幅改写不采用，整段保留原始转写后重新校验，不能借回退绕过数字、否定、专名或必须纠正的重复字幕锚点。所有内容分析使用同一份已验收文案。
2. 只生成四个模块：选题结构与人群、表达价值与行动、画面镜头、综合判断。模型采用有界的紧凑协议返回标签索引、少量结论和证据引用；程序恢复稳定ID与时间。模块级校验保留材料状态、标签合法性、同源段落和信息单元要求。
3. 前三个模块最多并发两个，综合模块最后执行。旧版兼容字段由同一结果转换产生，不再独立生成旧主体和专项长报告。
4. 校正及每个成功模块保存带来源、模型和协议签名的检查点；只补失败模块，来源变化才使关联缓存失效。记录安全错误类型、HTTP状态、结束原因、推理用量、实际用量、起止时间及复用情况。
5. 视觉批次有限并发，保留首帧、开头与连续帧组，增加逐批进度和用量。内置视觉适配器确认不依赖OCR后，在首帧OCR成功时与后续OCR重叠执行；第三方适配器保持串行兼容，帧数和模型请求数不变。取得的URL原片保存在本安装的私有媒体库中，页面按实际时间定位，沿用公司/项目鉴权与Range读取。取证检查点保存前的进程中断仍可能需要重做该阶段。

MiniMax兼容参数按其[官方OpenAI协议文档](https://platform.minimax.io/docs/api-reference/text-openai-api)核对；M3.1 Flash 保持低推理强度，输出额度同时考虑推理与最终JSON，仍设硬上限。

## 报告和页面

默认生成 `analysis.v11`，包含 `unified_report: unified-report.v1` 和现有 `content_analysis: content-analysis.v1`。后者继续用于65维标签和跨视频统计；新旧版本都保留。

新版页面顶部显示整体状态、核心结论及复制口播入口。四个内容模块各自呈现结论、相关标签及可展开的原文/画面证据。失败模块只显示一次原因及单独重试入口。校正差异和原始转写折叠展示，保留少量有用媒体指标。删除独立视觉完成卡、技术说明、审计分数、任务诊断面板与空分类卡；不再把旧版15块正文和65张分类卡同时铺开。技术用量和失败记录保留在后台，供排查使用。

历史版本采用历史展示入口，选中报告的任务、转写、画面与版本一致。证据按钮必须实际定位到播放器的相应秒数；尚无本地原片时明确显示来源链接，不能伪称已定位。

## 验收

- 离线回归覆盖数字/专名保护、OCR冲突、完整逐段映射、紧凑协议非法引用、截断增长、服务繁忙、有限并发、模块恢复、权限撤销、历史版本及局部失败。
- 使用用户这条真实视频及现有模型配置验收：校正与原片一致，四模块完整且有有效证据，旧报告与新报告只展示一份组织结构；无重复双报告模型调用，定位与复制可用。
- 记录新旧实测分阶段耗时与调用数，不承诺未经测量的固定提速。先用已有证据调通模型协议，再用同视频重新取证的端到端任务检查视觉、存储与进度。
- 完成桌面/手机实际页面检查、必要全量回归与Windows验证。真实视频验收通过之后才提交推送GitHub；安装包经独立验收后发布。所有真实任务与模型输出仅保存在被忽略的本机状态/验收目录，不纳入源码。
