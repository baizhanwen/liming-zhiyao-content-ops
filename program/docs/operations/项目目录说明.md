# 项目目录说明

这份说明用于帮助开发人员和非技术同事快速判断文件职责，避免误删本地业务数据。

## 日常入口

最外层日常可见内容只保留 `program/` 文件夹和三个批处理入口：

- `start-local.bat`：仅本机访问时启动项目。
- `start-lan.bat`：同一局域网内团队协作时启动项目。
- `stop-local.bat`：停止网页和视频分析服务。

Git 仓库必需的 `.git/`、`.gitignore` 和 `.gitattributes` 保留在外层并设置 Windows 隐藏属性；资源管理器开启“隐藏的项目”时仍可看到，这是保留版本管理的预期行为。不要为了整理目录删除或迁移它们。

其余程序文件、配置、文档、依赖和数据都在 `program/` 中。项目概览与更新记录位于 `program/docs/`，不再放回外层。首次安装使用 `program/setup-local.bat`；备份、恢复、Cookie 和分析器安装等维护入口位于 `program/tools/`。下文路径均以 `program/` 为根目录，npm 命令也在这里执行。

## 源码目录

| 目录 | 职责 |
| --- | --- |
| `app/` | 页面、路由和服务端 API |
| `components/` | 前端业务组件 |
| `lib/` | 内容生成、分析、权限等核心业务逻辑 |
| `db/` | 数据库结构与运行时访问 |
| `drizzle/` | D1/SQLite 数据库迁移 |
| `services/analyzer/` | Python 视频下载、转写、OCR 与分析服务 |
| `tests/` | Node 自动化测试 |
| `scripts/` | 被启动入口和 npm 命令调用的内部脚本 |
| `worker/` | Cloudflare/Vinext 运行入口 |
| `build/` | 构建插件源码，不是构建结果 |
| `public/` | 网站静态资源 |
| `resources/` | 授权知识等可复用原始资源 |
| `docs/产品使用手册.md` | 当前版本各功能的操作说明 |
| `docs/architecture/` | 仍有效的权限、方法论和授权边界 |
| `docs/operations/` | 本地运行与目录维护说明 |
| `tools/` | 低频人工维护入口 |

## 本地数据与依赖

以下目录体积较大或会自动生成，通常已经被 Git 忽略：

| 目录 | 内容 | 能否直接删除 |
| --- | --- | --- |
| `.local/` | Cookie 快照、日志、进程状态和授权知识同步缓存 | **不能随便删除** |
| `.local/dv/`、`.local/delivery-verification/` | 交付验收时创建的独立测试安装及依赖副本 | 验收进程结束后可归档或清理 |
| `.local/stability-runs/`、`.local/launcher-tests/` | 自动化测试生成的隔离数据和临时脚本 | 测试结束并保留所需报告后可清理 |
| `backups/` | 人工创建的本地备份 | **确认不需要后再删除** |
| `backups/maintenance/cleanup-backups/` | 2026-09-10 清理与修复的原始备份 | 归位不等于释放磁盘空间；需要回滚时保留 |
| `.local/archive/` | 已结束测试的安装副本、报告和历史日志 | 按日期归档；不作为当前运行数据 |
| `.local/maintenance/` | 目录整理的移动清单与文件校验记录 | 仅用于核对与恢复路径 |
| `services/analyzer/model-cache/` | OCR、转写等模型缓存 | 可重建，但重新下载耗时 |
| `services/analyzer/.venv/` | Python 分析环境 | 可重建，需重新安装依赖 |
| `node_modules/` | Node.js 依赖 | 可通过 `npm ci` 重建 |
| `.wrangler/` | 本地 Cloudflare D1/R2 运行数据 | **不能随便删除** |
| `.next/`、`.vinext/`、`dist/` | 构建缓存和构建结果 | 停止服务后可重建 |
| `outputs/` | 本地打包产物 | 确认不再需要后可删除 |
| `services/analyzer/build/` | Python 打包时复制的源码 | 安装或打包结束后可清理 |
| `__pycache__/`、`.ruff_cache/`、`tsconfig.tsbuildinfo` | 解释器、检查器和类型检查缓存 | 相关进程停止后可重建 |

## 整理原则

1. 程序根目录配置文件如 `package.json`、`vite.config.ts`、`wrangler.local.jsonc` 必须与代码一起留在 `program/`。
2. 不把框架约定目录随意合并，否则构建和运行工具可能无法定位。
3. 不把 `.dev.vars`、Cookie、数据库或模型密钥提交到 Git。
4. 移动启动入口后，必须同步更新 README、界面提示和自动化测试。
5. 清理体积前先备份，优先清理可重建缓存，不动业务数据。
6. 没有直接 import 不代表无用：页面和 API 路由由框架发现，`db/schema.ts` 由迁移工具读取，动态类名和依赖包的 peer dependencies 也需保留。
7. 2026-09-10 清理的历史测试安装、旧交付包和热修复包现位于 `backups/maintenance/cleanup-backups/cleanup-20260910/archived/`。旧报告中的 `F:\liming-zhiyao-content-ops-main\cleanup-backups` 前缀已失效，应替换为当前 `program/backups/maintenance/cleanup-backups`；原始记录保留不改写。恢复时按清单中的原相对路径取回，避免用旧热修复包或旧数据库覆盖当前数据。
8. 后续修改完成前检查外层目录：不新增 README、CHANGELOG、截图、日志、交付包或清理备份。正式文档进入 `docs/`，维护备份进入 `backups/maintenance/`，临时验证文件留在 `.local/`，结束后按需归入 `.local/archive/日期/`。
9. 不搬动脚本仍直接引用的依赖，例如 `.local/ecommerce-browser/node_modules/`；运行中的日志、状态文件和用户素材也不按临时文件处理。
