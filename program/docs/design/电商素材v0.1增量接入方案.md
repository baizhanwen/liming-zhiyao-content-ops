## 1. 目标与实施原则

用户选择一个真实 SKU，明确本次受众、购买障碍、一个主卖点及其证据；系统选择适配的方法组件和对标结构，生成可拍摄的脚本，展示应用依据，支持局部替换，并将人工回填的发布结果关联回具体版本。

这属于中等规模的业务扩展，包含商品资料、生成、审核和结果回填，不是增加一个提示词。第一版按可验收的小阶段实施，不同时建设完整电商中心。

降低对现有功能的影响采用四个约束：

- 内容生产内增加电商入口，普通内容仍进入原页面和原生成接口。
- 电商任务、版本、引用和结果独立保存，不把电商资料追加到普通内容的提示词中。
- 复用现有认证、公司与空间权限、视频身份、模型连接、调用计费和审计基础设施。
- 默认关闭，按试点空间开启；任何阶段都能单独关闭电商入口及写接口。

不能承诺绝对零影响：数据库迁移、共享模型额度、公共页面组件和服务资源仍是交叉点。每个交叉点都必须有明确改动清单和回归验收。

## 2. 当前项目约束及接入决策

| 已核实的现状 | 接入决策 |
| --- | --- |
| `content_items.topic_id` 非空且唯一；内容列表、生成和工作流通过 `INNER JOIN topic_ideas` 查询 | v0.1 新建电商任务表，不为商品任务伪造选题，也不修改旧任务的选题约束 |
| 现有普通创作与单条对标共用内容生成接口，`creationMode` 为 `standard` / `single_benchmark` | 电商是业务任务类型，不增加为现有 `creationMode` 的第三个值；使用独立接口与提示词 |
| 现有 `productionPackSchema` 为严格结构，包含普通口播输出与引用类型 | 新建电商输出结构，兼容的显示组件可以复用，不直接把商品字段塞入旧版本 JSON |
| 发布、排期及审核记录绑定 `content_items` 和 `content_versions` | 第一版在电商任务详情提供最小审核、发布登记和复盘，独立存储；统一审核中心和发布列表留待后续适配 |
| 项目记忆只用于灵感，灵感不自动创建选题 | 电商生成不读项目记忆；本次不修改灵感和选题之间的关系 |
| 核心策略固定读取，内容支柱不强制限定每次生成 | 电商沿用核心策略的定位、受众和风格；具体 SKU、场景与转化目标由本次任务确定 |
| 已有授权方法目录与规则路由，但没有完整的商品适配元数据 | 基于现有授权资产整理电商组件，不把整份飞书文档直接喂给模型，也不宣称现有分类已经够用 |
| 当前指标表主要覆盖播放、互动等数据 | 电商成交、退款和消耗单独扩展，未采集与真实 0 分开处理 |

### 与老板原建议的调整

保留六类业务资料和“任务—生成—回填”的目标。五个业务页面先作为内容生产内的子页面提供，不增加五个一级菜单。

“复用现有审核发布”需分两步：第一版复用权限及交互习惯，保存电商自己的审核发布记录；后续再把两类任务接入统一列表。原因是当前业务表与查询强依赖选题，直接改造会扩大影响范围。

## 3. v0.1 范围

交付范围：一个商品、一个主要购买障碍、一个主卖点、一条短视频方案；支持自然流或付费素材的任务标签，以及商品点击、直播进房、成交三类目标。第一批只验收一个选定平台和一种目标，其他组合逐步扩展，不把“可填写平台”当作“已经验证适配”。

首批试点建议从“真实 SKU → 自然流短视频 → 商品点击”开始。用户能取得完整资料和后台结果是试点前提；没有真实 SKU 时可以做合成数据测试，但不能算业务验收通过。

不在本版范围：订单、物流、库存同步、投流执行、直播中控、自动发布、自动采集成交数据、经营战略决策、趋势预测、大规模团队任务改造。库存只是带更新时间的人工记录，不是库存管理系统。

## 4. 页面与操作路径

内容生产顶部增加“普通内容 / 电商素材”切换。电商入口仅在已启用空间显示；普通内容保留现有普通创作和单条对标仿写。

| 子页面 | 第一版功能 | 界面重点 |
| --- | --- | --- |
| 商品资料 | 新建 SKU、卖点与证据、内部字段、顾虑和表达禁区 | 每条卖点能展开证据与确认人；内部信息单独分组 |
| 素材组件 | 查看钩子、可视化方法、结构、SOP；人工导入与确认 | 搜索与任务适配标签；显示来源和使用限制 |
| 新建任务 | 选择商品，填写人群、场景、障碍、卖点、证据与目标 | 必填项渐进展开，允许保存不完整草稿 |
| 素材装配台 | 参考方案、脚本、镜头清单、依据、局部替换、审核 | 主区域看稿件；右侧按需展开应用说明，避免满屏诊断卡 |
| 发布与复盘 | 登记作品与实际版本，回填指标，记录后续动作 | 未采集显示“未填”；区分播放、转化和成交数据 |

一条任务的操作顺序：选择商品 → 填写任务 → 查看推荐及适配理由 → 生成 → 核对事实和拍摄可行性 → 局部调整 → 审核 → 人工发布登记 → 回填结果。

生成前允许人工替换系统推荐的开头、结构、证据表现方式；不要求用户逐张确认所有卡片才可生成。缺少关键事实或找不到适配组件时，明确列出缺项。

## 5. 六类资料的字段与边界

### 5.1 商品卡

必填：名称、SKU、公司与空间、品类、谁买谁用、使用场景、至少一个主卖点及其证据、不能说的内容（可明确填写暂无）、资料确认人及时间。

按任务条件填写：当前售价、币种、规格、活动与有效期、商品承接链接或直播间。使用价格钩子时，价格和活动条件必须有效；未提价格的任务不强制录入价格。

内部字段：成本、毛利、库存、原始退款和差评原因。内部字段不进入创作模型输入、公开稿件或公开导出。需要将售后问题用于任务时，由人工整理为不含内部数字与客户个人信息的“购买顾虑”。

卖点逐条结构化保存：`claimId`、表述、事实/主张类别、证据 ID、适用 SKU 与条件、允许表达范围、有效期、确认状态。不能只保存一大段商品介绍。

确认状态：草稿 → 待确认 → 已确认 → 已过期/已撤回。人工确认与“实验证明”分别标记；确认人签字不自动构成效果证明。

### 5.2 人群与场景卡

记录使用者、购买决定者、当前处境、触发购买的原因、替代解决办法、未下单原因、对价格/品质/效果的具体担心、平台与观看情境、信息来源。

v0.1 随商品或任务保存结构化快照，暂不建设独立人群管理中心。AI 推测标为“假设”；未经确认的假设可以帮助设计表达，但不能生成“所有用户都如此”等事实断言。

### 5.3 可调用素材组件

一个组件承担一个功能。必备字段：ID、版本、类别、名称、操作规则、解决的问题、适用目标/商品/平台/形式、所需信息、禁用条件、输入输出结构、来源定位、授权范围、确认状态。

四组核心组件：钩子、卖点可视化、素材结构、拍摄 SOP。投放和复盘规则可保留分类，但本版不执行投放操作。

“有结果数据”和“经人工确认可用”分开记录；播放量高只说明播放表现，不能标记为成交有效。

首批人工挑选小规模组件集，例如 10–20 个钩子、5–10 个演示方法、3–5 个结构及相应 SOP；这些是试点建议数量，不是必须填满的上线门槛。关键是每张卡都能解释适用与不适用条件。

### 5.4 爆款案例卡

关联现有 `video_id`、当前空间对标引用 ID、分析 ID 和转写版本；只增加电商拆解资料，不复制原视频。

记录目标人群、转化目标、钩子机制、卖点出场位置、证据方式、承接动作、可迁移结构、依赖博主人设的部分、观察到的指标及其来源。

电商首版外部案例只用于结构与表达机制参考，不用来证明本商品效果、销量、身份或客户反馈。没有成交后台资料时，“是否有真实成交数据”必须为未知，不能由播放量推算。

### 5.5 电商任务卡

生成必填：商品版本、目标人群与场景、一个主要购买障碍、一个主卖点 ID、证据 ID、平台、自然流/付费标签、转化目标、承接位置、目标时长、实际拍摄条件。

可选：指定参考案例、指定钩子/结构、明确勾选的品牌知识、补充要求。未选品牌知识不自动补入；已选商品只读本任务所需的公开事实。

本次目标与账号策略明显冲突时，生成前提示具体冲突，由用户调整任务或明确本次例外，并保留记录；不能悄悄改写账号策略或把任务改成另一个主题。

### 5.6 结果复盘卡

关联：任务 ID、实际发布版本 ID、商品版本 ID、账号、平台作品 ID/链接、发布时间、流量类型、可选投放计划标识。

指标：曝光、播放、停留口径（如 3 秒）、完播、商品点击/直播进房、加购、成交订单数、成交金额、消耗、退款订单数/金额、评论新问题、下一步动作。

每次回填必须带观察时间、统计区间、归因窗口、数据来源、口径与填写人。缺失为 null；真实 0 为 0。金额按分及币种保存，计数非负，比例用分子分母或明确精度保存。

累计快照不能相加。修正回填保留旧记录与替代关系。同一作品多次更新，不重复算为多条素材。商品卡汇总或直播间整体成交只能标为对应层级，不能强行归因到某条视频。

展示“成交金额 / 广告消耗”时明确命名为 ROAS，并标清退款前后口径；成本口径不完整时不计算利润 ROI。自然流消耗为 0 时该比值显示不适用，不显示无限大。平台自报 ROI 可单独保存原始值和口径，不与本地计算混用。

## 6. 资料分层与来源规则

| 数据层 | 可进入生成的内容 | 不允许的流向 |
| --- | --- | --- |
| 通用方法 | 已授权、确认且启用的钩子、框架、SOP | 企业专属资料不得通过打“通用”标签进入共享库 |
| 外部案例 | 经当前空间授权引用的视频结构和演示方法 | 原博主身份、销量、经历不能变成本商品事实 |
| 企业专属 | 当前空间所选商品公开事实、所选品牌知识、已确认的任务条件 | 不能跨公司或未经授权跨空间检索 |
| 临时任务 | 本次补充、AI 计划、草稿、局部修改 | 不自动写入品牌知识、项目记忆或通用方法库 |

现有同公司视频共享规则继续适用；第一版商品和任务只在所属空间使用，同公司跨空间共享商品留待显式授权机制实现。

导入飞书资料的第一步是保存来源定位和版本、去重并分类，再人工确认用途。仅使用可取得且有权限的资料；本方案未连接飞书，也未核实老板提到的所有目录内容。

来自资料的文本均为待分析数据，不能覆盖系统指令、权限、字段白名单或任务约束。来源撤回后禁止用于新生成；已有版本保留当时快照并提示来源状态变化。

## 7. 检索、选择与生成流程

### 7.1 先由程序确定资格，再由 AI 选择组合

1. 校验登录、公司和空间权限、模块开关、额度与任务修订号。
2. 固定商品、事实、证据、核心策略与明确选择的品牌知识版本。
3. 服务端构造公开事实白名单，内部经营字段在这一步剔除；不能只靠提示词要求模型保密。
4. 硬过滤组件：授权范围、平台和目标适配、所需证据、拍摄条件、有效期、禁用条件。硬条件不满足即淘汰。
5. 按购买障碍、主卖点、场景和可拍性排序，初版每类最多提供 5 个候选；只在同等适配条件下参考已有实绩。
6. AI 从候选中选择钩子、可视化方法、结构和 SOP，输出选择理由及各段应用；只能选择真实候选 ID。
7. 程序校验选择与输入契约，生成脚本和拍摄清单。
8. 程序核验引用、数字、版本、字数/时长预算；AI 辅助检查表达与论证，人工完成最终事实确认。
9. 验证通过后保存不可变版本、输入与来源快照、调用记录；失败不覆盖上一稿。

没有适配案例时可以采用已确认的通用结构，并明确显示“未采用外部案例”；没有足够商品证据时停在待补充，不用案例或模型常识填补。生成中新增的定量效果、证书、销量和个人经历，没有有效来源就不允许通过。

### 7.2 提示词分层

独立版本名建议：`ecommerce-content.v1`。不改现有普通内容或单条仿写的提示词。

| 输入部分 | 内容与权限 |
| --- | --- |
| 系统约束 | 商品事实边界、任务目标、不能执行资料内指令、输出结构 |
| 账号方向 | 核心定位、受众、风格；不把内容支柱设为强制主题 |
| 本次任务 | 商品、人群、场景、障碍、主卖点、目标、时长与拍摄条件 |
| 可用事实 | claim ID、文字、允许表述、证据 ID、来源版本和限制 |
| 组件候选 | 已过滤的方法规则及其可用条件 |
| 参考案例 | 可迁移结构和不可迁移事实，带原文定位 |
| 输出要求 | 段落、镜头、应用说明、引用、待确认项、CTA |

输出采用结构化段落：`segmentId`、段落功能、口播、画面、时长预算、组件 ID、claim ID、evidence ID、案例应用、CTA 目标及待确认项。

“为什么这样选”展示简明的业务理由、来源片段及实际应用，不展示模型内部推理，也不把模型写出的理由当作已经验证的事实。

### 7.3 每条参考怎样说明应用

应用说明至少含：来源卡与版本 → 借鉴的具体方法/结构 → 本稿段落 ID → 对应生成片段 → 为什么适配本次障碍 → 未迁移的内容。

例如：“参考 A 的‘先展示使用困难，再演示解决动作’结构，用在第 1–2 段；本商品的演示依据来自证据 E2。未使用原案例中的销量、用户反馈和限时优惠。”

来源报告区分“提供给模型”“实际采用”“未采用及原因”。不能将所有候选都显示为已引用，也不能只给整条视频一个笼统的‘借鉴结构’标签。

## 8. 局部替换及版本规则

支持替换开头、证据演示或 CTA。用户指定区域后，模型返回目标段落的补丁；服务器保留其他段落原文，并以哈希校验未修改区域。每次替换形成新版本，保留父版本、修改范围和新增调用费用。

替换依赖要明确：改变证据可能使正文主张失去支持，改变 CTA 可能与承接目标冲突。发生这类情况时显示受影响段落并要求调整范围；不能为了满足“局部修改”保留已不成立的表述。

第一版先做完整生成与人工编辑，再做三类局部替换。电商“选择一个案例”初期只约束段落结构，不直接承诺现有单条仿写的 85%–115% 字数规则；如后续提供严格单条仿写模式，应单独接入并验收。

## 9. 技术实施边界

路径均相对 `program/`，以下为计划新增，并非已存在。

| 层 | 建议位置与职责 |
| --- | --- |
| 页面 | `app/content/ecommerce/`：商品、组件、任务详情及复盘子页面 |
| 接口 | `app/api/ecommerce/`：独立鉴权、读写、生成、替换、审核和结果回填 |
| 业务代码 | `lib/ecommerce/`：字段白名单、组件筛选、生成输入、引用校验和指标口径 |
| 数据 | 新增 `ecommerce_*` 表及增量迁移；不修改历史迁移文件 |
| 公共复用 | `db/runtime.ts`、`lib/request-auth.ts`、`lib/model-adapter.ts`、组织额度和审计工具 |
| 导航 | 仅在 `app/content/page.tsx` 或其导航组件增加受开关控制的入口 |

建议数据实体如下；实际 DDL 在实施阶段按查询与约束落实，首版以结构化 JSON 保存稳定快照，避免为每个标签建立一张表。

| 拟新增表 | 关键内容与约束 |
| --- | --- |
| `ecommerce_project_settings` | 公司/空间、启用状态、并发与调用上限；默认关闭，仅管理员可管理 |
| `ecommerce_products` / `ecommerce_product_versions` | SKU 身份、当前版本；公开事实、内部字段、场景和顾虑分区；同空间 SKU 唯一 |
| `ecommerce_evidence` | 证据类型、原始附件或资料定位、适用主张、确认/过期状态、版本与哈希 |
| `ecommerce_components` / `ecommerce_component_versions` | 方法卡身份与不可变版本；通用和企业专属的服务端范围规则 |
| `ecommerce_case_profiles` | 原视频/项目引用/分析版本、电商拆解；同范围及分析版本去重 |
| `ecommerce_tasks` | 商品关联、任务输入、当前稿件版本、流程状态、输入修订号、操作者 |
| `ecommerce_versions` | 完整脚本与段落、镜头清单、来源快照、应用说明、验证结果、父版本 |
| `ecommerce_generation_runs` | 任务/基础版本、幂等键、输入哈希、调用关联、开始/结束/失败状态 |
| `ecommerce_reviews` | 指定版本、审核结论、意见、审核者；编辑后原审核不再适用于新版本 |
| `ecommerce_publications` | 实际发布版本、账号、作品链接与时间；不随任务当前版本自动改绑 |
| `ecommerce_metric_snapshots` | 发布 ID、观察时间、归因口径、指标、回填来源与修正关系 |

所有企业业务表携带 `organization_id` 与 `project_id`，通过服务端可信权限限定。关联对象也要核对相同范围；仅检查任务所属公司还不足以防止跨公司引用商品或附件。

通用组件仅由可信的授权导入流程发布。普通企业成员不能提交 `system=true` 之类参数把私有资料升级成全局资源。

模型连接复用现有内容模型配置，新增可识别的 `model_calls.task_type`，但不改普通内容的默认路由。电商消耗计入公司总额度，另设模块并发/调用预算，避免挤占普通生成。每次计划、生成、校验或修订调用均计费并记录；整次生成建议最多 5 次调用，超过预算时返回可操作错误。

当前 `project-generation-context.ts` 的能力和来源类型不含商品、证据和电商任务。第一版建立电商自己的上下文与来源校验器，复用认证、冻结检查和哈希基础能力，并将经验证的 manifest 写入现有审计表。不能把商品伪装成 `knowledge`，也不能为了通过校验放宽普通生成的来源限制。

核心接口契约：任务修改带修订号，生成/替换带基础版本及幂等键；发布登记显式指定已审核版本；回填只接受属于当前空间发布记录的 ID。生成写版本与更新当前版本要原子完成，并发冲突返回 409；重复提交不创建重复版本或重复扣费。超时后先查询运行记录，不能无条件重新发起模型调用。

## 10. 状态与发布门槛

任务业务状态：草稿 → 待审核 → 待发布 → 已发布 → 已复盘/已归档；审核退回进入草稿并保留审核意见。生成执行状态单独保存为等待/运行/成功/失败，不替代任务业务状态。

关键门槛：

- 生成：必填条件齐全，选中事实和证据有效，商品与附件范围一致。
- 提交审核：没有未解决的事实缺口，镜头方案和承接动作可执行。
- 审核：针对指定版本确认商品主张、来源与拍摄可行性；不把模型自检等同于人工审核。
- 登记发布：版本已通过审核，录入实际平台作品或链接；记录的是人工发布结果。
- 复盘：至少有一组带时间及口径的数据，缺项允许为空，不要求为了完成流程编造订单。

已发布稿再修改时形成新的待审核版本，旧发布记录仍指向原稿。价格或证据失效不篡改旧版本，但新生成及新发布前必须重新核对。

素材保存、人工确认、已经发布、已有可核验结果分别记录。仅发布一次或录入高播放量，不会自动把资料标记为“成交有效”，也不会自动写入企业知识库。

## 11. 分阶段实施与验收

| 阶段 | 交付内容 | 完成条件 |
| --- | --- | --- |
| A：隔离基础 | 功能开关、独立路由、增量建表、最小导航 | 关闭开关时旧功能表现不变；无权限请求被拒绝；旧数据恢复演练成功 |
| B：资料可用 | 商品/证据、组件导入确认、案例关联、任务表单 | 一个真实 SKU 能填完整；内部字段不会进入公开输入；组件能按条件淘汰 |
| C：完整生成 | 确定性筛选、计划、脚本、镜头、引用报告、版本 | 每条商品主张可定位；证据不足可解释地中止；失败保留上一版 |
| D：调整与交付 | 三类局部替换、审核、手动发布登记 | 未选段落保持原文；编辑后重新审核；发布绑定实际版本 |
| E：结果与试点 | 手动回填、指标口径、应用效果关联、试点开关 | 能从结果追到作品、版本、商品、组件；普通内容回归通过 |

A–C 可作为内部演示，但只有 D–E 也完成才算 v0.1 闭环交付。人群中心、统一审核列表、跨空间商品共享、批量投放实验和平台接口另列后续版本。

每阶段先完成一个端到端样本，再扩充资料，不先导入数百张未经确认的卡片。开发工期要结合首批资料质量和真实模型调用验证估算，此方案不承诺固定天数。

## 12. 回归与验收用例

| 场景 | 必须验证的结果 |
| --- | --- |
| 普通内容生成、单条仿写、口播改写 | 原输入契约、来源范围、校验和版本行为保持；不出现商品提示词 |
| 项目记忆与灵感 | 记忆继续只进入灵感；灵感不自动创建选题 |
| 旧内容列表、审核、发布和指标 | 历史记录可读可操作，不因新表导致关联缺失或重复 |
| 新旧数据库安装 | 全新安装和从基线迁移均成功；旧业务表行数与关键字段校验一致 |
| 跨公司/跨空间请求 | 替换任务、商品、证据、案例、媒体 ID 均不能越权 |
| 敏感字段 | 输入夹带毛利/库存等字段也不能混入公开事实白名单；日志与导出检查通过 |
| 外部案例有高销量或人设经历 | 生成不能把这些内容归属到试点 SKU 或当前账号 |
| 证据缺失、过期、撤回 | 生成明确阻止或要求更换；原版本保留快照 |
| 没有推荐命中 | 展示无匹配原因，不随机选取无关组件 |
| 模型返回不存在的来源 ID | 校验拒绝；不给不存在的引用补造数据 |
| 局部替换 | 未改区域哈希一致；新主张重新检查；冲突时不静默改整篇 |
| 超时、重复点击、并发编辑 | 幂等与乐观锁生效；不覆盖新稿，不产生重复运行或无界重试 |
| 已发布后再次生成 | 老作品仍指向原版本，复盘不跟随最新稿漂移 |
| 缺失数据和真实 0 | 展示与计算不同；重复快照不重复累计；不能从播放推断成交 |
| 关闭电商功能 | 入口及写接口关闭，运行中的请求在最终写入前复核开关；已发生调用仍记账，普通流程可用 |

基线版本曾通过 341 项 Node 测试、146 项 Python 测试、类型检查、构建和 lint；实施验收以届时全部测试为准，不能把基线通过视为新增功能已验证。新增测试优先覆盖权限、数据流、幂等、版本和指标口径，不只匹配界面文字。

## 13. 开关、上线和回退

1. 在独立开发分支实施；每阶段单独提交，保留可追踪的迁移与验收记录。
2. 迁移前暂停相关写入，备份数据库、媒体关联与本地配置，并在副本验证恢复；禁止使用空数据目录覆盖现有目录。
3. 迁移只新增电商表及索引，不删旧表、不重写旧版本 JSON、不更改旧状态含义。
4. 先开一个试点空间，验证真实 SKU 的完整链路；普通功能回归和模型资源限制通过后再扩大启用范围。
5. 功能异常首先关闭电商生成和写入，保留历史只读查看；已验证可兼容时回退应用代码，新增表保留。
6. 只有确认数据库需要恢复时才执行恢复方案，并评估恢复点之后的新增普通业务数据；不能为回退电商而直接覆盖整库。

同进程中的 CPU、模型额度和数据库资源仍可能影响普通功能。因此除了功能开关，还需要请求大小、候选数量、模型调用次数与并发限制，以及失败率、耗时和额度的观察。

## 14. 实施前的资料准备与文档收尾

代码和当前数据库结构已经能在本地核对，无需重复索要。真实试点还需要：一个有后台数据权限的 SKU、确认过的商品事实与证据、少量有来源权限的组件资料、一个确定的平台和转化目标。上述资料是业务验收依赖，不阻塞先做独立路由、权限和合成数据测试。

开发完成后，将已实现行为同步到使用手册、数据流契约和更新记录；本方案的待办与阶段清单届时删除，未完成的后续设计单独保留。不要在完成之前删除实施依据，也不要提前把未来能力写成现有功能。

完成前持续以本文核对范围；技术验收和真实商品试点验收分别记录，未完成的部分不得标为已交付。
