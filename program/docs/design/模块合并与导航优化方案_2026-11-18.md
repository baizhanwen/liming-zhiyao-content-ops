## 建议的整体结构

建议将通用内容运营整理为五个主要入口，电商中心独立呈现，工作台继续承担任务概览与快捷操作。

| 建议入口 | 内部结构 | 主要用途 |
| --- | --- | --- |
| 素材中心 | 分析任务、当前空间对标、公司素材 | 从视频分析到保存素材、选择本项目参考 |
| 创作中心 | 灵感、选题池、稿件；口播改写作为创作方式和快捷入口 | 从想法、已有选题或原稿开始，形成可审核稿件 |
| 审核发布 | 审核、发布；排期归发布内部 | 审核意见、退回修改、待发布及发布登记 |
| 数据报告 | 数据概览、数据导入、作品匹配、周期报告 | 查看表现、补齐数据、生成企业及员工报告 |
| 空间资料 | 空间概览、品牌知识、内容策略、项目记忆 | 管理当前空间的基础资料、方向及经验 |
| 电商中心 | 独立一级入口，内部结构另行规划 | 保留商品及电商文案业务的独立工作流程 |

顶部保留公司与企业空间的当前范围及切换入口。全部空间列表、新建和归档等管理操作，可从空间切换入口进入“管理企业空间”；侧栏的“空间资料”服务于当前选定空间。

公众号图片的归属本轮暂不调整，后续再判断是否作为通用创作的专用方式。成员与权限、系统设置继续承担管理职责。

## 各组合并的判断与关键设计

### 素材中心与对标内容库

适合合并，建议同时将视频分析收进同一入口。分析任务负责处理进度，素材列表负责复用，当前空间对标负责标明本项目选择了哪些参考；有高频需求时，可在工作台保留“分析视频”快捷操作。

当前三种视图已经共用 `/analysis` 和 `AnalysisWorkspace`，其中素材与对标使用 `VideoLibraryWorkspace` 的不同模式，具备先整理导航的基础。

公司素材与当前空间对标仍须有明确范围切换，默认优先显示当前空间。素材进入对标库代表建立引用，同一视频可以供多个空间复用。“移出当前空间”不能变成删除原视频、分析结果或其他空间引用。分类、标签目前属于公司素材的共享属性，修改时应显示影响范围。

### 选题灵感口播改写与内容生产

适合归入创作中心，但内部应保留“灵感、选题、稿件”三个工作阶段。口播改写是从现成原稿开始的一种创作方式，可放在新建入口和稿件页快捷操作中，无需再占一个独立主菜单。

合并需要补齐两个实际断点：

1. **灵感转为选题。** 当前保存或采纳灵感不会创建选题。后续应提供明确的“转为选题”操作，保留来源、允许补充目标及所需品牌资料，并避免重复创建；单纯保存灵感仍保留原有含义。
2. **改写结果进入稿件任务。** 当前口播改写有独立工作区和版本。后续应允许把指定改写版本纳入内容任务，保留原稿、来源及改写记录，再接入审核发布；合并入口本身不能完成这条关联。

用户有明确题目时应能直接从选题或稿件入口开始；已有原稿时应能直接改写，不要求先走灵感对话。统一页面后，也不能默认将全部品牌资料、项目记忆和历史文案输入正文生成。

### 审核中心与发布管理

适合直接合并为“审核发布”。当前已经共用 `/workflow` 和 `WorkflowWorkspace`，可优先收敛主菜单，保留审核、发布两个内部视图，并在发布视图承接排期。

审核必须对应具体稿件版本；改稿后按现有规则重新审核。待发布、预约发布、发布失败和已发布仍是不同状态。当前发布以准备、排期和真实发布结果登记为主，入口合并不表示已接入平台自动发布。

### 数据复盘与报告中心

适合合并为“数据报告”。当前已经共用 `/insights` 和 `InsightsWorkspace`，内部保留数据概览、导入、作品匹配、报告四个视图即可；报告中继续区分企业运营报告与员工工作报告。

数据看板反映当前数据，已定稿企业报告保留当期快照，二者不能因入口合并而自动同步覆盖。作品匹配仍是从平台指标回溯稿件及主创的必要步骤。企业与员工报告继续遵守各自的查看范围。

### 企业空间品牌知识与项目记忆

适合在“空间资料”中集中访问，但企业空间仍是整套系统的工作范围，顶部切换应保留。空间列表与创建管理属于跨空间操作；品牌知识、策略、记忆属于选定空间内部的资料，不能全部混入同一列表。

建议当前空间内提供概览、品牌知识、内容策略、项目记忆四个视图。品牌知识保留已确认事实及版本，项目记忆保留带来源的经验、候选和人工采纳状态。现有规则是已确认且明确选择的品牌资料用于选题和正文，已采纳有效记忆辅助灵感；页面合并不改变资料的用途。

原知识页受开关控制的授权方法论入口也需保留，它属于方法来源，不等同于当前客户的品牌事实。共享视频不会把来源空间的品牌知识、记忆一起共享。

### 电商中心独立板块

用户已明确电商中心后续独立，不归入通用创作中心，也不作为其下的一个页签。本次按同一系统内的独立一级板块记录，是否独立部署或拆成单独应用不在本次需求内。

建议电商中心保留商品资料、商品证据、文案任务和对应版本的独立组织方式。与素材、模型服务或通用审核发布的复用关系，后续单独设计，需保持商品、任务和稿件来源可追溯。独立板块不自动扩展为订单、支付、成交归因或 ROI 功能。

## 建议实施顺序

新增首页、改写和视频数据需求后，详细实施批次以最终 PDF 的依赖关系为准。以下模块合并顺序作为可独立推进的导航整理路径。

1. **先整理导航。** 优先统一素材与对标、审核与发布、复盘与报告的入口，沿用现有页面和数据；明确电商中心的独立位置。
2. **整理空间资料。** 保留全局范围切换，将品牌知识、策略、记忆组织到当前空间内部，并区分业务资料与管理操作。
3. **打通创作流程。** 再完成灵感转选题、改写结果纳入稿件、来源和版本追溯，减少复制粘贴与重复录入。
4. **单独规划电商中心。** 确定内部结构和与共享能力的连接方式，再安排对应改造。

入口合并优先复用现有数据模型。涉及状态关联、版本、权限或历史记录的后续改造，需在实现时单独设计，避免为减少菜单而迁移或混合全部数据。

## 工作台与员工工作进度

珍珍同学提供的工作进度台截图用于参考任务摘要、状态筛选、任务进度条、更新入口和动态记录。建议沿用项目现有品牌视觉，将首页主体整理为紧凑概览、筛选及任务列表；任务说明和进展历史进入详情，最近更新可折叠。视频分析队列、审核明细、月发布目标等详细列表归相应业务板块。

管理员首页默认关注团队工作，员工首页默认关注自己被分配的工作。任务不局限于内容运营，例如“开发客户管理项目”“完成需求文档”“整理素材”。开发项目可以关联企业空间，也可以属于公司内部工作，无需为派一项工作强制创建客户空间。

| 操作 | 建议功能 |
| --- | --- |
| 管理员派发 | 明确任务标题、工作说明、交付要求、负责人、截止时间、优先级；空间关联和阶段步骤按需填写 |
| 员工更新 | 填写 0–100% 进度、本次进展、下一步、等待协作或阻塞说明、成果链接 |
| 管理员查看 | 查看团队和单个员工的任务、进度、到期及逾期、等待协作、未更新情况；可按空间与任务类型筛选 |
| 历史记录 | 每次更新保留时间、填写人、原进度、新进度及说明；重新打开任务保留原历史 |

现有自定义任务前端只有“完成任务、重新打开”；后端的手动数量更新也不等于完整的百分比填报。首页表单尚未提交任务标题，现有同员工、同空间、同类型不能重复派未完成任务的限制也不适合多个开发工作并行。后续应复用任务基础，补齐上述能力。

员工工作进度按用户要求自主填写。系统视频分析等运行进度仍保留实际测量，现有自动业务数量可作为参考，不覆盖员工自报的工作进度。首页现有月发布目标也不能替代开发任务完成度。

建议默认对任务等权汇总，同一筛选范围内已完成计 100%，取消任务不计入。未填进度显示“待更新”，不伪装成 0 或 100%；有未填项时展示“已填任务平均进度”和“已填 X 项、待填 Y 项”，全部填报后再称为整体进度。长期复杂任务可选拆成阶段，阶段权重另行明确。

## 口播改写质量品牌适配与模型

建议链路为：原稿解析 → 检索当前企业空间相关且已确认的品牌资料 → 识别待适配名称与身份 → 按选定方式生成 → 核对品牌归属和事实 → 检查口播质量 → 保存版本、资料快照及替换说明。

当前口播改写没有读取品牌知识，而且提示词和硬校验要求保留原品牌、产品及事实标识。品牌适配需要同时调整输入上下文、实体映射、生成提示词、校验及修订；只改提示词或换模型会与现有规则冲突。

用户要求的自动品牌识别应限定在当前公司和企业空间，优先读取已确认、与本稿相关的名称、简称、产品、服务与官方表述，并允许查看采用的资料。企业适配可用于自我介绍、品牌推广和行动引导；外部人物、案例及竞品比较保留原归属。原作者的客户数量、成绩、价格和承诺不能仅随名称一起移植，无依据的信息应提示补充或采用有依据的表达。

提示词优化除事实保留外，应关注口语自然度、开头吸引力、论点推进、信息密度、冗余、品牌融入和结尾行动引导。当前代码约束通过不代表真实文案质量已通过，需要以用户现有问题稿进行改前改后对照。

模型选型需查询当前官方文档，区分候选与已实测结果。建议以同一批中文口播、长稿和品牌适配样本比较输出质量、事实与名称错误、结构化输出成功率、耗时及实际费用；先固定提示词比较模型，再固定模型比较提示词。评估口播改写独立用途配置，并保留回退。品牌资料版本和适配目标纳入生成快照与复用条件，避免跨企业复用结果。

2026-11-18 已核对官方文档的候选为 `qwen4-max`、`deepseek-v4-pro`、`kimi-k3.1-pro`、`gemini-3.8-flash`，以 `deepseek-flash` 作为成本与响应速度对照。以上主要型号均为待评测候选，不代表已证明优于当前接入模型，也未执行本项目实际稿件盲评。按审阅意见新增的 Gemini 3.8 Flash 是稳定版，支持约 100 万输入上下文、多模态与结构化输出，接入时核对地区可用性并适配思考参数。官方来源：[Qwen4-Max](https://help.aliyun.com/zh/model-studio/qwen4-max)、[DeepSeek 模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)、[Kimi K3.1 Pro](https://platform.kimi.com/docs/guide/kimi-k3-1-pro-quickstart)、[Gemini 3.8 Flash](https://aistudio.google.com/docs/models/gemini-3.8-flash)。

整体模型优化应按内容生成、口播改写、分析文本、视觉理解和项目助理分别评估，优先解决改写质量。上述短名单主要供文本任务使用，文本表现不能替代视觉任务的样本验收。

本次新增的品牌自动检索适用于口播改写；其他选题和正文生成继续沿用原有资料选择规则，除非后续另行调整。

## 视频评论封面指标与可视化

当前已存在视频发布时间及赞评藏转播的指标快照结构，旧采集分支可填部分数据；默认匿名采集主要传递作品 ID、标题与时长。新增工作应补齐默认采集链路，而非重建所有指标存储。各字段以实际返回为准，发布时间与采集时间分开记录，未知保持缺失，不填 0。

现有素材封面主要取自关键帧，应新增平台原封面及来源标记，保留视频截图回退。指标刷新与昂贵的原片重新分析分开，只有真实多次采集的数据才形成历史走势。

平台评论区与团队审稿评论是两种记录，需新增评论、回复、去重、样本范围、排序方式和时间信息。评论分析单独展示高频问题、需求、异议和反馈主题，保留评论原文依据及样本数量；评论样本不足时明确覆盖，不能把部分热门评论当作全部反馈。

二维图表按审阅意见移除点赞量与评论量的关系散点，保留横轴发布时间、纵轴点赞量的分布、素材表现排行及单视频按采集时间的指标趋势。排行按相近发布时长与观察窗口比较，帮助筛选参考内容。支持按企业空间、账号、日期范围筛选，点选定位原视频，并提供表格及导出。

原片内容、评论反馈和传播指标分别组织证据。原片事实依据继续来自转写、字幕和画面；传播表现及评论可辅助运营判断，不能仅由点赞高低推导某个钩子导致传播。实际平台字段及评论获取能力须通过目标入口验证。

## 后续验收重点

- 一个内容任务在选题、稿件、审核、发布、复盘之间能追溯，不因跳转丢失当前公司、企业空间或选中内容。
- 灵感和口播改写有明确的下一步动作，并能核对是否已成功转入，避免重复创建。
- 公司共享素材与项目资料的可见范围明确；移出对标不会误删素材。
- 改稿后的审核要求、发布登记、企业报告定稿快照及员工报告权限继续有效。
- 电商中心有独立一级入口，商品和文案任务的历史记录保持可访问。
- 原有链接、历史稿件、原稿与版本仍可定位；空空间与无权限状态提供明确指引。
- 管理员可同时给同一员工安排多个具体工作，员工可填写中间百分比与说明，管理员能看到保存后的更新及历史。
- 进度汇总展示任务范围与填报覆盖，未填项保持待更新；系统自动运行进度不被员工自报覆盖。
- 改写能应用当前空间已确认品牌名称，保留外部案例归属；缺失知识、资料失效及跨空间引用有明确处理。
- 提示词与候选模型使用同一组真实问题稿对比，记录质量、事实错误、结构化成功率、耗时及合格稿成本，再决定接入方案。
- 评论分析可回查原评论及样本范围；原封面与视频截图来源清楚；发布时间、采集时间、缺失指标分别呈现。
- 二维图表与素材筛选、详情及导出联动，单次快照不能生成历史走势；图表与表格使用相同数据口径。
