# 分析串行与受控并行

新分析默认选择受控并行，可在链接提交、本地上传或重新分析时切换为串行。每个任务独立保存设置；失败重试保留原值，重新分析可重新选择，历史任务兼容为串行。处理方式只控制调度，不改变画面档位、口播校对、分析内容或模型调用额度。

串行按口播准备、画面处理的顺序执行。内置受控并行先完成本地抽帧、筛选及 OCR，随后重叠执行云端画面理解和本地口播准备。主机仍一次处理一条视频，云端看图保持原有的并发限制。它不保证固定的提速比例，也不代表自动判断整机内存是否充足；电脑卡顿时可选择串行。

纯音频、已复用原稿、没有可重叠视觉步骤，或视觉处理器未提供准备完成通知时，保守采用串行。完整分析的报告和诊断分别记录请求方式、实际方式及可用的回退原因；旧报告缺少该字段时不按新默认值重标。仅提取口播稿也按串行处理，其原有空报告协议保持，不写额外的执行元数据。

原始转写仍独立保存检查点，视觉失败后可在有效检查点恢复。并发分支不各自写任务租约，视觉分支具有独立的有界时限；取消或超时继续由隔离进程负责回收。画面与口播耗时可能重叠，诊断中不能将它们直接相加为总时长。

数据库迁移为 `0055_analysis_execution_mode.sql`。升级应等待现有任务结束、按项目原有流程备份并应用迁移，然后重启网页与分析服务。已有数据、配置和旧报告保留，不自动发起分析。

本机自动化验证与 Windows 原机性能验收分别记录。原机验收应使用同一条授权素材、相同画面档位与分析设置，比较串行和受控并行的总耗时、语音与画面重叠、CPU/内存峰值，并检查取消、失败后重试和下一条任务。未实测前不宣称用户原机已提速。
