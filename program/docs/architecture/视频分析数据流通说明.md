# 视频分析与内容生成数据流

核对日期：2026-09-15。本文描述当前实现；趋势观察和预测仍是未来设计。路径相对 `program/`，不包含本机业务数据快照。

## 局域网队列、资源归属与恢复

同一安装的所有公司和项目共享一个执行名额。数据库原子领取与 Windows 安装路径互斥锁共同限制执行；启动器持有启动锁，守护进程与 Worker 分别持有生命周期锁。Worker 监测真实守护父进程的句柄，避免 PID 重用带来的误判断。

Worker 将处理子进程加入 Windows Job Object 后才允许开始工作。父进程退出或主动关闭 Job Object 时，处理子进程与 FFmpeg 等后代一并回收。健康子进程连续复用模型；取消、超时或异常退出后重建。取消接口先修改任务状态和版本，暂留租约，处理停止后的 release 请求按 Worker 与累计领取轮次释放名额；迟到结果与旧轮次释放请求不能覆盖新执行。失联期间无法确认释放时，名额等租约过期回收。

迁移 `0049` 的数据库触发器在同一写事务里检查个人 10 条、安装 50 条未结束任务；跨项目累计个人数量，取消后未释放资源的任务仍占位。重试归属本次操作者，领取次数累计作为执行标识；每次显式重试重新给予最多 3 次自动领取机会。恢复优先处理未执行的等待任务，避免坏任务反复抢占队列。

### 时限

默认初始化 1800 秒、下载 900 秒、媒体规范化 900 秒、语音与画面并行提取共计 1800 秒、证据入库 600 秒、结构模型阶段 1800 秒，整条任务 7200 秒。通过 `.dev.vars.example` 中 `ANALYZER_TIMEOUT_*_SECONDS` 配置，允许值为 30～86400 秒；旧配置缺少这些键时使用默认值。

媒体时长超过 600 秒的部分，标准模式按每秒增加 1 秒、最高能力模式按每秒增加 2 秒，为媒体、证据和结构阶段分别追加预算，单阶段最多追加 14400 秒。任务总时限另按媒体时长的两倍追加，最多 14400 秒。恢复检查点也应用时长预算。初始化与长视频实际处理速度仍需目标主机校准。

主进程每 2 秒检查取消与执行权；阶段预算只在切换阶段时重新开始，重复心跳不会延长阶段总时限。ASR 和视觉共用一个有限的证据阶段预算，正常长推理不按缺少细小进度变化误判。取消和超时回收的自动测试目标为 10 秒内释放本地资源，真实环境需复核；已经发往外部模型的请求不保证撤销，也不保证免除费用。

### 调用记录与故障边界

迁移 `0050` 的 `analysis_model_calls` 在每次结构分析、报告续写、校正文稿或证据修复请求前记录调用，结束时写入供应商提供的 Token 用量。记录不含提示词、Cookie 或密钥。同一任务重试保留历史，未收到最终用量的调用明确标为未知，不能记为免费。独立视觉引擎仍使用原有视觉统计，其供应商费用需结合实际账单核对。

结构模型 SDK 不再隐式重试；报告在可恢复 JSON 时最多续写一次，文稿校正最多两轮并保留原文与事实校验。恢复完整文稿 JSON 不发起额外调用；不完整或超限的段落明确失败。证据和已完成分段检查点继续复用，连续执行崩溃达到上限时停止自动领取并显示可操作的错误。

## 来源与存储

| 资料 | 主要存储 | 使用边界 |
| --- | --- | --- |
| 视频及原始来源 | `videos`、`video_library_entries` | 同一视频保留原身份，项目通过引用复用 |
| 项目对标 | `project_video_references` | 仅当前空间有效的 benchmark 引用可被选作对标 |
| 完整转写 | `video_transcripts` | ASR/人工版本，用于分析和原稿读取 |
| 分析与证据 | `video_analyses`、`video_knowledge_atoms`、`media_assets` | 证明视频中的内容，不自动变成客户事实 |
| 视频指标 | `video_metric_snapshots` | 区分真实 0 和未采集，不等于预测能力 |
| 品牌知识 | `knowledge_items`、`knowledge_item_versions` | 使用已确认且由选题明确勾选的资料 |
| 内容策略 | `content_strategies` | 固定读取定位、受众、基本风格和任务默认目标 |
| 项目记忆 | `project_memory_items` 及证据/版本表 | 已采纳且有效的记忆用于灵感，不直接进入选题或正文 |
| 灵感 | 对话、消息、`project_inspiration_cards` 及来源表 | 手动保存，不自动创建选题 |

## 1. 分析与共享素材

提交视频后，经分析任务保存转写、结构化报告和附件。公司素材库通过原视频 ID 关联资料；导入当前空间建立引用关系，不复制另一份视频。

跨空间复用需通过所属公司的有效素材引用。撤销对标只解除该空间的使用关系，不删除原视频或历史分析，也不让源空间的品牌知识、项目记忆跟随共享。

视频重新分析保留旧报告。分析完成、候选记忆提取完成、用户采纳完成是不同状态；不能用其中一个状态代替其他阶段。

## 2. 选题输入

用户输入 + 核心内容策略 + 明确勾选的品牌知识 + 明确指定的视频来源 → AI 补全 → 保存选题及引用。

品牌知识选择保存在 `selected_knowledge_ids_json`，正文生成沿用这份明确选择。未选择时不自动读入品牌知识、项目记忆、历史文案或无关视频片段。内容策略属于方向指导，不证明个人经历；内容支柱不强制限定本次题目。

## 3. 普通内容生产

选题与明确事实 → 方法计划 → 所选对标（最多 5 条） → 生产包 → 引用校验 → 不可变版本。

已选对标提供最新分析文本、可用的视频指标及当前空间复用反馈。可以选择性借鉴相关问题、观点、方法或有归属的外部案例；不能把来源的身份、数字、成绩或经历移植成用户事实。

每条已选对标保留引用和应用说明。引用只证明来源可定位，不证明推理必然成立或内容一定有效。只有引用缺失时进入引用修复，保留已有正文；不能通过编造出处通过验收。

历史文案和部分旧引用类型保留解析与审核兼容能力，不表示当前生成会自动读取这些资料。

## 4. 单条对标仿写

选择新选题与 1 条当前空间对标 → 读取完整校正原稿或转写 → 拆分连续功能段并映射新题 → 逐段生成 → 检查和修订 → 独立校对 → 保存。

- 原稿支持 40–8000 字，不以分析摘要冒充全文。
- 总字数目标为原稿的 85%–115%，程序计算逐段目标和允许偏差。
- 模板决定钩子机制、功能段顺序、衔接和 CTA；通用方法只辅助清晰性与事实检查。
- 修订带回实际上一稿、各段当前字数及目标，最多两轮定向修改；不截断正文，不用放宽标准伪装通过。
- 原稿、计划、每段应用和对照报告保存在版本的 `pack_json`；人工编辑后标记生成时对照已过时。
- 模型校对不是事实审核的替代。个人经历与承诺仍需明确资料支持。

## 5. 项目记忆与灵感

有效对标分析 → 记忆提取事件 → 独立项目助理 → 候选 → 人工采纳 → 灵感上下文检索。

提取兼顾内容经验、问题、观点、案例线索和表达方法。视频候选证据需要匹配实际输入分析的原文；旧提取版本可分批重查，不一次性覆盖全部已采纳内容。

灵感对话读取当前空间对标、核心策略、相关已采纳记忆和对话历史。记忆引用须有可核验的来源快照；保存时再次检查记忆有效性。不满足新引用契约的历史引用不自动升级为有效来源。

灵感生成、保存或采纳不创建选题中心记录。对已有记忆的 AI 转述不算新的独立证据。记忆模型与内容/分析模型分别配置，未配置时不暗中借用另一模型。

## 6. 发布与反馈

内容版本 → 审核与修订 → 发布记录 → 指标导入或回填 → 复盘与对标推荐反馈。

稿件的对标来源关联、平台作品匹配和发布指标各有自己的关联记录。仅看到某个平台作品的数据，不代表该作品已经与某份稿件版本对应。复用反馈只作为参考信号，不证明某个钩子导致了成交或播放增长。

目前没有商品任务、订单或电商 ROI 链路，也没有全平台热点预测。
