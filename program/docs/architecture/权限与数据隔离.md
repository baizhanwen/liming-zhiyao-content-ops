# 权限与数据隔离基线

## 信任边界

浏览器提交的 `organization_id`、`project_id` 和角色都不可信。服务端必须先从认证身份查出有效公司成员关系，再查项目成员关系，最后把可信范围注入查询。

```text
认证用户
→ 有效 organization_members
→ 有效 project_members（公司管理员除外）
→ 查询同时限定 organization_id + project_id
→ 写操作记录 actor、目标和时间
```

## 当前角色

| 身份 | 主要权限 |
|---|---|
| 公司管理员 | 管理公司、企业空间、成员、授权、配额和系统设置；默认可访问全部企业空间 |
| 公司员工 | 仅访问管理员已分配的企业空间；在空间内拥有分析、素材、知识、选题、创作、审核、排期、发布和复盘等全部业务权限 |

企业空间不再设角色，只记录员工“已分配 / 未分配”。旧的负责人、策划、创作、审核、客户和只读记录在迁移后统一为已分配员工。

## 强制规则

- 跨公司访问直接拒绝，不返回目标是否存在。
- 非公司管理员必须具有有效项目成员关系。
- 公司员工必须先被分配到企业空间，才能读写该空间的业务数据。
- 只有公司管理员能管理公司、空间、成员、授权、配额与系统配置。
- 成员移除使用状态停用，历史审计记录保留。
- 邀请只保存令牌哈希，必须有过期时间且一次性使用。
- 媒体对象键使用 `organizations/{organization_id}/projects/{project_id}/...` 前缀。
- 重要更新带版本号；长任务使用组织范围内唯一的幂等键。
- 物理删除由异步任务执行，并写入审计日志。
