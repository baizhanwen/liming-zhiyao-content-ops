# 电商素材数据流与版本约束

对应实现：`app/api/ecommerce/`、`lib/ecommerce/`、`components/ecommerce/` 与增量迁移 `0048_ecommerce_foundation.sql`。业务上线与真实 SKU 验收状态以实施验收记录为准，本文件描述已实现的代码契约。

## 独立接入

普通任务的 `content_items.topic_id`、普通创作和单条仿写输入契约保持原状。电商使用 `ecommerce_tasks`，不生成占位选题，不增加普通 `creationMode` 值。普通内容页只增加受空间开关控制的入口。

电商资料、版本、运行、审核、发布和回填均有独立表。复用认证、公司与空间成员权限、视频身份、内容模型连接、公司总额度、模型调用记录及审计基础设施。因此额度和服务资源仍与原功能共享，并非完全独立的服务。

新空间默认关闭，管理员设置电商并发数与月调用上限。写接口先检查开关，关键最终 SQL 再检查开关、权限和来源状态。关闭后历史记录仍可读；取消与恢复已有运行允许继续执行。

## 事实与方法

```text
确认过的商品版本（基础资料，或单一卖点 + 明确选择的有效证据）
  + 明确选择的品牌知识
  + 可选核心策略（定位、受众、风格）
  + 内置内容方法论；仅选择参考视频时加入唯一案例
→ 完整输入快照及来源清单
→ 创作思路与结构计划 → 稿件 → 规则校验与独立校对
→ 必要的一次定向修订并重新检查
→ 新的不可变稿件版本
```

生成不查询商品内部 JSON，不读取项目记忆、灵感聊天或历史发布文案。品牌知识仅使用明确选中的当前已确认版本。内容策略去除内容支柱、人设与默认阶段目标；本次转化目标由任务决定。

前端只有一个生成入口，通过「是否参考视频」控制来源。默认不参考时按内置内容方法论选择钩子与结构；不要求策略、方法卡或视频。选择参考时只迁移唯一所选案例的叙事机制。方法指南已固化在 `copy-methodology.ts`，运行时不依赖文档目录或文件系统。

方法原文由 `scripts/build-ecommerce-methodology.mjs` 编译到 `resources/ecommerce-methodology.v2.json`，记录真实文档、源行、原段落、SHA256与覆盖范围。修改原始资料后运行 `node scripts/build-ecommerce-methodology.mjs` 更新，`--check`校验一致性。运行时筛选任务相关候选；计划选定具体ID后只保留所选钩子、主框架及最多一个补充框架的原文。计划用固定步骤编号，服务端按所选框架附上原句；事实计划同样用短编号定位商品原文，不依赖模型重抄长ID与引文。

历史与高级任务仍可使用已确认的开头和结构方法卡，按平台、转化目标、品类、证据类型、活动信息、有效期和禁用条件筛选，每类最多五个候选，计划每类选一个。没有完整卡组且未明确指定时回到内置方法论；明确指定的失效卡不能静默忽略。拍摄、画面与 SOP 卡不进入文案生成。

未手工指定主张与证据时，服务端根据当前已确认商品版本投影基础事实和虚拟来源 ID，不写入证据表。最终 SQL 仍核对空间、商品确认人、当前版本、修订号与完整基础资料快照；客户端不能伪造虚拟来源。用户录入卖点只用于表达重点，不能自动证明功效、销量或认证。

`copyFacts`补充具体内容、使用例子、差异、交付、限制与讲述者真实经历，全部随公开商品版本确认。生成前的`copyReadiness`只使用本次实际可用的商品资料与所选证据，不借未选主张或参考案例填充分性。明显贫乏资料在首次模型调用前返回具体缺口，仍允许商品草稿保存。

案例绑定当前空间有效对标引用、原视频、分析与可选转写。原文引用必须能在实际分析文本或转写中定位，不把 JSON 键名当来源。案例只提供结构与表达机制；作者经历、销量和效果不是商品证据。编辑案例递增修订号并撤销确认，旧稿保存的输入快照不变。

商品主张、证据、知识、方法和案例都进入来源清单。每条提供的来源必须报告采用或未采用；采用项记录原文、真实稿件片段、段落及理由。校验拒绝无效 ID、无法定位的引文、应用与段落不一致、缺少必要事实支持或超出篇幅/时长预算的稿件，不补造引用。

独立校对检查语义是否被证据支持，包括无引用段落中可能新增的事实，以及钩子兑现、单一卖点、行动理由与参考改写。轻微口语风格偏好不阻止通过。它不替代人工审核，也不能把人工确认升级为实验事实。提示词、方法论版本及来源、创作思路随稿件保存，旧版本不会因提示词更新重算。

## 运行与并发

一次运行有幂等键、任务修订号、基准稿件版本和调用次数，最多五次模型调用。同一幂等键的参数不允许改变；重复请求读取原运行。任务乐观锁、空间并发限制、电商月调用上限和公司总调用额度共同生效。

生成结束前重新读取来源并比较输入哈希，最终写入继续检查商品、证据、组件、知识、案例、核心策略、成员关系与任务版本。失败或状态变化不覆盖原稿。

取消把运行结束，但未返回的调用继续计入占用。迟到结果不保存。管理员只能在连续五分钟无调用活动后回收中断运行；回收保留调用记录与费用，不自动重试。

浏览器区分结构化拒绝和传输结果不明。结果不明时保存原幂等请求到当前会话存储，重新进入任务继续核对；不自动重新生成。页面切换保留未保存提醒。

## 版本、审核与结果

完整生成、人工修改、开头/证据/CTA 局部替换均新增稿件版本。局部补丁只能更新选定角色的段落，服务器合并并校验其他段落一致。人工修改允许保存待修正草稿，审核仍须通过有效性检查。

任务按草稿、待审核、可发布、已发布、已复盘、已归档流转。审核绑定版本；任务条件或稿件改变后不沿用原审核。稿件的待确认事项必须解决才能提交。审批要求商品事实、承接位置两项人工确认。

发布登记核对当前已审核版本、当前空间有效自有账号、平台和流量类型。作品永久关联当时稿件版本，后续新稿不迁移历史作品与结果。自有账号登记仅支持抖音元数据，不连接平台。

观测数据使用不可变累计快照，修正通过 `replaces_id` 指向被替代记录。空值与零不同，不跨快照累加；商品或直播整体数据不能归因到单条视频。ROAS 以成交金额/广告消耗计算，金额和退款口径保留；平台自报 ROI 单独记录定义。

结果追溯接口从实际发布版本读取来源快照和 `used=true` 应用项，因此显示的是当时实际采用的方法和事实，不是当前最新候选。复盘不把相关性解释为成交因果，也不会自动把 AI 草稿升级成企业知识或已验证方法。
