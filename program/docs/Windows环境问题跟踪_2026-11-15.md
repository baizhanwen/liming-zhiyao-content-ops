用户后续截图显示上次检查时间为 `2026-11-15T12:37:14Z`（北京时间 20:37:14）：Qwen3-ASR CPU 中文转写通过，环境配置任务执行完成并启动服务，但 Whisper GPU 仍为 `CUDA_LIBRARY_UNAVAILABLE`，日志具体错误仍是 `Library cublas64_12.dll is not found or cannot be loaded`。因此本轮原机 GPU 验收仍失败，不能因配置任务完成而关闭 W01/W02。

截图未包含 CUDA 准备阶段的完整原因，尚不能区分运行库准备失败、被跳过或未按预期加载。下一步读取该安装 `program/.local/model-cache/models-ready.json` 的 `cudaRuntime` 与 `timingAsr`，按实际记录继续定位。配置任务“执行完成”目前表示自动模式下 CPU 基础环境可用并已启动，不代表 GPU 通过。

## 设置里的最终入口

1. **打开页面／自动刷新**：读取上次验证和文件元信息，不运行 GPU 转写，不下载安装。
2. **重新检查**：重新加载基础依赖；适用时以独立、限时子进程运行现有中文样本，显式 CUDA、仅本地模型、不允许自动 CPU 回退。服务运行中或无法确认停服时不抢占显存，显示本次未执行的原因。
3. **一键配置环境并启动**：按平台/设备准备缺失依赖；Windows NVIDIA 首次运行库归档合计约 541 MiB，来源为 NVIDIA 官方固定版本与 SHA-256，不修改 torch、驱动或系统 PATH。随后验证样本，再显示实际结果。
4. **正式分析**：使用相同受校验的项目运行库与加载模块。`auto` 出错保留 CPU 回退和真实原因；明确 `cuda` 保持严格语义，不悄悄改成 CPU。

GPU 状态分为未验证、准备/加载/实际转写失败、已经完成实际验证。CPU 环境可用与 GPU 验证分开展示，历史结果注明时间；配置、实现或 DLL 元信息变化后不能继续冒用旧验证。

## 依据与仍需完成的验收

[CT2 4.8.5 加载实现](https://github.com/OpenNMT/CTranslate2/blob/v4.8.5/src/cuda/cublas_stub.cc#L48) 用同一错误报告缺文件/无法加载；该版本[官方 Windows 构建](https://github.com/OpenNMT/CTranslate2/blob/v4.8.5/python/tools/prepare_build_environment_windows.sh#L50) 使用 CUDA12.8.1 且 `WITH_CUDNN=OFF`，所以本轮没有额外下载整套 cuDNN。组件版本与归档校验来自 [NVIDIA 官方清单](https://developer.download.nvidia.com/compute/cuda/redist/redistrib_12.8.1.json)。

本机已验证官方约 3 MB cudart 归档的真实 SHA-256 和 DLL/许可证解压；cuBLAS 只读取约 128 KB ZIP 目录，核对了实际 DLL/许可证路径，没有在 Mac 下载或运行整套 Windows cuBLAS。行为测试使用小型合成归档，不能替代 Windows 实际加载。

剩余验收：原机执行运行库准备并通过 CUDA 短音频；升级后的设置页“重新检查”和“一键配置”分别验证；原反馈视频验证完整分析、超时后复用 ASR 与取消后的资源回收；无 NVIDIA 和明确 CPU 的 Windows 环境验证跳过及降级。源码推送不代表 Windows GPU 已验收；本轮不发布 Windows 安装包。
