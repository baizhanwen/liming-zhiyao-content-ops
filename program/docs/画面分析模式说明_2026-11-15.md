# 画面分析模式

链接分析的“内部备注”标题右侧，与“提出口播纠错候选”并列选择画面分析方式。上传及报告的重新分析入口也可选择。默认沿用混合模式，原有口播纠错候选开关独立生效。

| 方式 | 画面文字 | 场景、人物和构图 | 本地 OCR | 口播 |
| --- | --- | --- | --- | --- |
| 混合模式（OCR＋视觉） | 本地 OCR | 配置的视觉模型 | 保留现有流程 | 原有语音转写及可选校对 |
| 纯视觉模式 | 配置的视觉模型读取清晰可见文字 | 同一视觉模型 | 不初始化、不执行画面 OCR 或字幕对齐 OCR | 继续原有语音转写；纠错候选仍由独立开关控制 |

## 使用与恢复

- 选择保存在每条任务中。重试只补失败部分时保持原模式，重新分析可以切换。
- 历史任务缺少模式字段时按混合模式处理。新增数据库迁移为 `0053_analysis_visual_mode.sql`。
- 转写、取证检查点及报告缓存校验模式；切换模式使用新任务，不能把混合模式结果标成纯视觉，也不能混用付费模块缓存。
- 素材导入及公司素材库复用保留模式；已有不同模式的报告不能静默替代本次选择。
- 纯视觉提交前校验支持的视觉适配器配置。模型不可用或全部画面理解失败时明确失败，不自动切回本地 OCR。
- 文字看不清时允许空字符串，不补写事实、专名或数字。仍执行正文、来源和时间对应校验。

## 图像输入与诊断

OpenAI 兼容视觉接口使用原始图片及 `detail=high`。MiniMax Token Plan 的工具入口一次只接受一个图片来源，因此纯视觉每次发送一张原图，不使用混合模式的六图缩略联系表；并发保持有界，缺帧最多再补一次。逐帧原图可能增加请求次数和云端用量，不能保证耗时与此前联系表方案相同。

MiniMax 原图单次请求只看到一张图，诊断明确标记 `temporal_model_input_supported=false`，不把该次请求冒充连续视频理解。既有抽帧覆盖、开头和时序采样规则保持不变；此次功能不解决采样数量预算问题。

报告及导出记录 `analysis_meta.visual_analysis_mode`，画面诊断含 `screen_text_source`、`ocr.status`、`ocr_engine_call_count` 和实际各阶段耗时。纯视觉的本地 OCR 状态为 `skipped`，调用次数及耗时为 0。现有 `Keyframe.ocr_text` 和证据 `source=ocr` 是兼容合同中的“画面识别文字”字段；纯视觉下内容来自视觉模型，报告说明与诊断显式标明该来源，不表示运行过 PaddleOCR。文字观察数量与实际理解帧数分开统计，不能增加覆盖率。

## 验证范围

本机离线分析器全量 1288 项通过、16 项跳过、139 个子测试通过；Node 全量 1656 项通过、38 项跳过。新增回归覆盖 OCR 零调用、字幕 OCR 跳过、原始口播保留、模式切换与缓存隔离、无视觉模型拒绝、原图输入、缺帧及有界重试、任务持久化、报告版本隔离及只读 JSON 导出。类型检查、构建及相关静态检查通过。

界面使用隔离合成 API 在真实 Chrome 验证提交、上传、重新分析和历史版本选择；不代表真实模型或 Windows 原视频验收。本机应用已先做数据库备份，再应用新增字段迁移；原有数据保留。

Windows 验收：升级后，用同一视频分别选择两种方式，保留相同分析档位及纠错开关，导出两份 JSON 比较。纯视觉应显示 `vision_only`、`screen_text_source=vision_model`、本地 OCR 零调用；同时人工核对清晰标题、数字、专名、关键演示画面及口播。真实耗时、云端用量和识字准确率以该实测为准，尚未在本次修改中完成。
