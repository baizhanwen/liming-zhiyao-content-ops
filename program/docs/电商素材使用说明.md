# 电商文案使用说明

当前流程：**补全商品信息 → 填写本次要求（参考视频可选）→ 生成完整文案**。输出包含标题与完整分段口播，不生成分镜表、画面方案或拍摄清单。

## 入口

从左侧「电商中心」进入，选择公司和企业空间。主要入口为「商品资料」「文案任务」，默认打开商品资料。

「制作第一条视频」「发布与复盘」入口已移除。商品卖点直接显示为一个文本框，文案生成使用同一个入口，通过「是否参考视频」选择创作方式。历史商品、任务、稿件和用量记录保留。

管理员可以点击「启用文案功能」，或在「空间设置」中启用当前空间并设置并发与每月调用上限。关闭后历史资料仍可查看，新保存与生成停止。公司模型额度同时生效。

## 1. 补全商品信息

填写商品名称、价格、品类、规格、使用者、购买决定者、使用场景、购买顾虑和表达禁区。常见情况可以直接选择，不适合时使用「自行填写」。价格按元输入，无需手填 SKU。

商品页不再显示「更详细的人群与购买判断」「价格、活动与承接链接」「内部经营资料」三个展开区；历史值仍保留。商品卖点直接填写在一个文本框中，每行写一个具体特点，不再要求手工填写类别、确认状态和证据关联；随商品资料一起确认保存。

核对资料后，保存为「已确认」，再点击「用此商品写文案」。商品资料与填写的卖点是本商品文案的事实依据，确认只表示有人核对过录入资料，不等于外部实验或第三方认证。

写稿资料增加「具体提供什么」「实际使用例子」，以及可选的差异、交付、适用限制和讲述者真实经历。课程可以写实际教什么、完成什么作业、给什么材料；实物可以写具体结构、操作或使用场景。不要只填“便宜、好用”或没有单位与含义的规格数字。资料不足时，系统会在调用模型前列出关键缺口，商品仍可先保存。

录入价格不能自动变成优惠、原价、限时活动或销量信息。已有促销信息仍受对应证据与有效期检查。内部经营资料不会自动发送给创作模型。

## 2. 选择是否参考视频

默认不勾选「参考视频」，直接根据内容生产方法论、当前商品资料与本次要求，由大模型选择合适的钩子与结构，生成一条从开头、主卖点和事实依据到结尾行动引导的完整文案。不需要准备参考视频、手工导入方法卡或配置内容策略。

方法论优先让开头在 3–5 秒交代具体问题，随后自然转入一个主卖点，用商品事实回应一个购买顾虑，再给出一个指定行动。只有名称、价格、空泛卖点或无含义的规格数字时，先补充具体内容或使用细节，再生成；不虚构实测、功效、销量、优惠或亲身体验。

方法按本次商品、顾虑、场景和可用证据筛选。生成计划须选择具体钩子与框架，并把框架步骤落实到实际段落。系统会附上所选方法的原文、章节、行号与哈希，随稿件保存。当前资料实际包含18类钩子、10个框架族结构、8类详细卖点方法及其余类目的通用建议；不将文件名里的“100种”冒充100张已存在的独立框架。

需要仿写时勾选「参考视频」，再选择一个当前空间已分析的对标视频。系统读取对应分析与文案，可展开预览；存在转写时默认选择最新转写，也可只使用分析报告。关闭参考会清除本任务的参考选择。

没有可选视频时，点击入口到对标内容库添加视频并完成分析。选择视频本身不会调用模型，也不要求另外填写一套案例档案。

生成会借鉴参考视频的开头、内容顺序和表达机制，把商品事实换成当前商品已确认的信息。原视频的作者身份、个人经历、销量、价格、效果、资质和用户反馈不能移植成我们商品的事实。

旧参考案例继续可以选择，也可以直接选择已分析视频。

## 3. 生成、编辑与导出

确认商品、是否参考视频、目标时长与观众下一步动作，按需补充本次要求，再保存并点击「生成完整文案」。任务不要求拍摄方式、出镜人员、场地或分镜信息。

商品的人群与场景会自动沿用；特殊情况可展开调整。内容策略为可选项，两种创作方式均可在未配置策略时生成；已配置时沿用当前空间的定位、受众和风格。

生成先从真实资料中选择有说服力的细节，说明其购买意义，再组织开头、场景、机制、取舍与行动。事实原文和方法步骤用固定编号定位，由程序附上准确原句。起草后执行规则校验和独立内容校对，逐项引用正文检查观看理由、购买判断价值、具体细节、口语表达、方法执行和行动理由。句句属实仍可能因空泛而不通过。可修复问题最多定向修订一次，修订后重新核查，每个运行最多五次模型调用；真正缺资料时要求补充，不编造填空。失败保留原稿。

目标时长用于约束篇幅，例如 30 秒建议约 120–150 字。文案工作区默认显示可连续阅读的完整稿，可一键复制全文或导出。「逐段调整」用于编辑与局部替换，「方法与依据」查看所选方法原文、实际段落落点和内容校对，「审核记录」处理审核。旧稿会明确标为尚未进行新版内容校对；运行记录位于稿件之后。

可以只替换开头、依据段或行动引导。人工修改后填写说明，保存独立新版本。导出仅包含标题和文案，不附带分镜或拍摄清单。

存在「待人工确认」时，应先核实问题或修改不受支持的表达，不能仅删除未解决事项来通过审核。审核只核对商品事实和承接位置，绑定具体版本；新稿不沿用旧审核。

## 4. 运行与历史记录

所有读取和保存按公司与企业空间隔离，并检查当前权限。遇到登录失效或版本冲突，先复制未保存内容，再刷新核对。

运行记录显示调用次数与失败原因。取消后已经发出的请求可能仍需等待返回，迟到结果不会保存；已经发生的调用与用量不会删除。

请求结果不明时使用「核对原请求」，沿用原运行标识。管理员可在连续五分钟无调用活动后恢复中断运行，该操作不会自动重新生成。

旧稿中的历史画面、拍摄字段和方法设置仍保存在历史记录中，当前界面与导出不展示。旧任务可以修改「是否参考视频」后生成；历史文案仍可查看和导出。

技术回归与合成数据验收不代表真实商品的销量、ROI 或投放效果验证。
