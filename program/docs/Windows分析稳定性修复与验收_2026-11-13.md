# Windows 视频分析稳定性：修复记录与实机验收

本轮目标来自 Windows 反馈：Whisper GPU 转写回退 CPU、转写完成后视觉阶段超时、重试重新转写，以及 `g.0.e` 返回 25 项而上限为 24 导致模块失败。代码修复保留“提出口播纠错候选”开关，默认不勾选仍用原始转写。

## 已实现的行为

1. **转写完成立即保存独立检查点。** 原片先存为受保护附件；ASR 原文完成后立即保存完整原稿和 `transcript_ready` v2，再继续字幕与视觉分析。恢复时校验源附件归属、大小、SHA-256、原稿哈希、ASR 配置与实现指纹、候选开关和人工原稿哈希。通过才复用原稿；不匹配不冒用。完整证据检查点继续优先复用。
2. **分阶段计算超时。** 语音、字幕、视觉分别计时，旧 `ANALYZER_TIMEOUT_EVIDENCE_SECONDS` 作为各阶段默认预算（1800 秒）。可分别设置 `ANALYZER_TIMEOUT_SPEECH_SECONDS`、`ANALYZER_TIMEOUT_SUBTITLE_SECONDS`、`ANALYZER_TIMEOUT_VISUAL_SECONDS`。附件预算仍由 `ANALYZER_TIMEOUT_ARTIFACTS_SECONDS` 控制。同阶段再次进入累计耗时，不重置预算；整条任务总时限、取消、子进程回收继续生效。
3. **保留 GPU 失败实因。** Whisper 初始化或懒加载推理失败时记录脱敏后的错误类型、分类和原始 DLL/运行时错误。只有完整执行解码后才称作 GPU 已验证。同一识别器的 CPU 回退继续复用，避免同进程每条视频重新尝试失败的 GPU。
4. **列表超限局部恢复。** 所有引用必须先通过索引类型与来源校验，再去重。仍超限的分类转为无法判断；事件、信息单元或结论整条省略，并清除依赖它的判断。保留其他经完整校验的结果；必要内容仍不足时只进行现有的有限修复。不把前 24 条引用当成完整证据。恢复路径、动作、项数写入 `diagnostics.local_recovery`，支持报告与检查点往返。
5. **上传与心跳不再争用同一个瞬时版本。** 新工作端用同一轮次的 `attempt_count` 作为附件/检查点/源文件读取的稳定边界，同时校验租约与 worker 身份。取消、过期租约、换 worker、旧轮次请求均拒绝；旧工作端保留原有版本校验。
   检查点写入同时比较已存 JSON 与阶段；并发冲突最多重读三次。同轮迟到的基线、已完成模块子集或分段窗口集合缩水不能覆盖较新快照；新一轮仍可重建缓存。
6. **进度可解释。** Qwen 上报真实已处理音频分段数（包含无声分段）；重试提示可复用口播继续。累计模型调用涵盖视觉等分析调用。

## 历史失败基线：独立诊断包使用方法

诊断包可直接用于反馈里的旧部署，无须先更新整个项目。它只检测 Whisper 的 CT2 CUDA 推理；当前 Windows Qwen 主模型使用 sherpa-onnx CPU，这个检测不会把 Qwen 变成 GPU 模型。

1. 等当前分析任务结束，记录其它占用显卡的应用；不要为本次诊断重装依赖或改 CPU/GPU 设置。
2. 当前使用 `Windows-Whisper-GPU-DLL定位-20261115.zip`，完整解压到可写目录（例如桌面新文件夹），再进入解压后的文件夹。不要在 ZIP 内直接双击 CMD 或只提取 CMD；Python 脚本、`gpu_diagnostics.py` 和自测 WAV 必须与 CMD 相邻，缺少任一文件时启动器会直接停止。11 月 13 日旧包不包含本轮 DLL 定位。
3. 双击 `diagnose-whisper-gpu.cmd`，输入项目目录，也可输入其 `program` 目录。不需要管理员权限。支持中文、空格、带双引号的粘贴路径和 `F:\项目\program\` 这样的尾部反斜杠。
4. 检测使用现有分析器虚拟环境、已缓存的 `large-v3-turbo` 和包内自测 WAV，禁用下载与 CPU 自动回退。CUDA 子进程默认最多运行 180 秒，驱动信息查询最多 10 秒；DLL 加载检查最多额外 30 秒。
5. 把窗口本次回显的完整路径所指向的 `whisper-gpu-result-*.json` 发回。每轮使用新文件名，不把旧 JSON 当作本次结果。未生成可读取的本轮报告时，启动器会报错并非零退出，此时发送窗口错误文字。报告已生成也不代表 GPU 通过；退出码 2 表示失败或未能检测，具体原因在本轮 JSON 中，不要因此先安装 CUDA。

诊断不会调用内容模型 API、提交视频任务、写业务数据库或安装依赖；可能创建本项目的缓存/诊断目录并由模型加载使用系统临时文件。JSON 不保存视频正文、密钥和完整环境变量。`passed` 表示这段自测 WAV 在 CUDA 上完整返回语音结果；`not_tested` 不能当作 GPU 故障结论。自测成功也不能代替长视频显存与吞吐验收。

## 更新修复代码后的业务验收

本机回归和模拟传输不等于 Windows 实机验收。收到 GPU JSON 后再按真实原因处理依赖/驱动或显存问题，随后对原反馈视频做以下验收：

| 验收项 | 操作 | 通过证据 |
| --- | --- | --- |
| GPU 定位 | 同一 Windows 部署运行诊断 | 有真实 CUDA 解码结果或完整脱敏错误；不以 GPU 数量、torch 版本或安装绿灯代替 |
| 原始转写模式 | 不勾选“提出口播纠错候选”分析 | 原文保留、显示未自动校对，无自动候选改稿调用 |
| 候选模式 | 勾选后分析 | 保留候选判断逻辑，待核对句有具体原文与候选入口 |
| 阶段独立预算 | 对原反馈视频运行 | 日志分别记录 speech/subtitle/visual/artifacts/model，不再累计为单一 evidence 超时 |
| 超时后复用 ASR | 仅在独立测试副本让视觉阶段超时，然后恢复正常预算重试 | 原任务已有 transcript_ready，重试提示复用口播；日志无第二遍 Whisper/Qwen 转写；原片哈希与原稿不变 |
| 超限局部恢复 | 若真实模型再次输出超过引用上限 | 报告保留其余有效结果，diagnostics 有局部恢复记录；无效引用仍不得通过 |
| 资源回收 | 测试副本取消或触发超时后再运行下一条 | 原子进程与辅助进程退出，下一条任务正常开始 |

不要为了生产验收改低正式安装的超时值。旧任务若没有新的转写检查点，首次重试仍可能需要重新转写；新检查点不能从当时未保存的原稿中凭空恢复。

## 2026-11-15：Windows 原机已返回失败基线

用户提供的 `whisper-gpu-result.json` 记录：2026-11-15 17:25:59（北京时间），RTX 4060 Laptop、驱动 596.36、总显存 8188 MiB、空闲 6060 MiB，Python 3.11.9、CTranslate2 4.8.5、faster-whisper 1.2.1。显式 CUDA、禁用 CPU 回退的短音频测试在 3.78 秒失败：

```text
status: failed
code: CUDA_LIBRARY_UNAVAILABLE
RuntimeError: Library cublas64_12.dll is not found or cannot be loaded
```

这是实际 Windows CUDA 解码失败的证据，确认失败点为 cuBLAS 动态库加载；不能只凭这句话区分“没有 DLL”“DLL 未被搜索到”或“DLL 的传递依赖/架构导致无法加载”。[CT2 4.8.5 原始加载代码](https://github.com/OpenNMT/CTranslate2/blob/v4.8.5/src/cuda/cublas_stub.cc#L48) 对这些情况使用同一错误文本。报告中的 `probe_exit_code=0` 仅表示诊断子进程正常返回结构化结果，不表示 CUDA 通过；通过与否看 `probe.status`。

核对精确版本后，CT2 4.8.5 [官方 Windows 构建脚本](https://github.com/OpenNMT/CTranslate2/blob/v4.8.5/python/tools/prepare_build_environment_windows.sh#L50) 使用 CUDA 12.8.1、动态加载 cuBLAS，并设置 `WITH_CUDNN=OFF`。因此先定位 cuBLAS，不能直接套用通用文档而要求此机器额外安装整套 cuDNN。当前项目锁定依赖中 NVIDIA 计算库属于 Linux 分支，未为 Windows 管理 cuBLAS。

下一步诊断只检查目标 Python 环境、标准 CUDA 目录和进程搜索路径中的 cuBLAS/cuBLASLt/cudart，并在独立子进程记录裸名称与绝对路径加载的 WinError。查到可用库后处理项目加载路径；确实缺库时再补最小官方运行库，并重新做显式 CUDA 短音频验收。

11 月 15 日 DLL 定位版已补齐以上功能。主报告进程直接管理加载检查的子进程，每次最多 10 秒、总预算 30 秒，不在 GPU 子进程内再创建加载子进程。路径清点只覆盖选定本地位置，不全盘扫描；`dll_inventory.status=missing` 表示在这些位置未找到完整的 cuBLAS/cuBLASLt 组合，不等同于全机绝对没有安装。27 项针对性测试通过，CMD 的 8 项静态/契约检查通过；新的 Windows DLL 清点与加载结果仍待用户返回。

供后续评审的官方运行库候选是 CUDA 12.8.1 的 cuBLAS 12.8.4.1（Windows x64 归档约 564 MB）与按需的 cudart 12.8.90。版本、下载体积与 SHA-256 以 [NVIDIA 官方再分发清单](https://developer.download.nvidia.com/compute/cuda/redist/redistrib_12.8.1.json) 为准；本次没有下载安装它们，也没有修改 torch、驱动或系统 PATH。

原始反馈及文件 SHA-256 记录在 `output/windows-stability-validation-20261115/`。启动器另补齐了缺少脚本时的完整解压提示、粘贴路径引号/尾斜杠处理，以及本轮独立 JSON 的生成与校验，避免启动失败却显示检测完成。
