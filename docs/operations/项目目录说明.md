# 项目目录说明

这份说明用于帮助开发人员和非技术同事快速判断文件职责，避免误删本地业务数据。

## 日常入口

项目根目录只保留四个常用批处理入口：

- `setup-local.bat`：首次安装网页依赖、初始化数据库与同步授权知识。
- `start-local.bat`：仅本机访问时启动项目。
- `start-lan.bat`：同一局域网内团队协作时启动项目。
- `stop-local.bat`：停止网页和视频分析服务。

备份、恢复、Cookie 和分析器安装等低频操作统一位于 `tools/`。

## 源码目录

| 目录 | 职责 |
| --- | --- |
| `app/` | 页面、路由和服务端 API |
| `components/` | 前端业务组件 |
| `lib/` | 内容生成、分析、权限等核心业务逻辑 |
| `db/` | 数据库结构与运行时访问 |
| `drizzle/` | D1/SQLite 数据库迁移 |
| `services/analyzer/` | Python 视频下载、转写、OCR 与分析服务 |
| `tests/` | Node 自动化测试 |
| `scripts/` | 被启动入口和 npm 命令调用的内部脚本 |
| `worker/` | Cloudflare/Vinext 运行入口 |
| `build/` | 构建插件源码，不是构建结果 |
| `public/` | 网站静态资源 |
| `resources/` | 授权知识等可复用原始资源 |
| `docs/product/` | 产品范围、施工说明 |
| `docs/architecture/` | 数据、权限和服务契约 |
| `docs/operations/` | 本地运行与目录维护说明 |
| `docs/research/` | 外部工具与技术调研 |
| `docs/design/` | 设计稿和视觉参考 |
| `docs/archive/` | 仅供追溯的历史审计资料 |
| `tools/` | 低频人工维护入口 |

## 本地数据与依赖

以下目录体积较大或会自动生成，通常已经被 Git 忽略：

| 目录 | 内容 | 能否直接删除 |
| --- | --- | --- |
| `.local/` | Cookie 快照、日志、进程状态和授权知识同步缓存 | **不能随便删除** |
| `backups/` | 人工创建的本地备份 | **确认不需要后再删除** |
| `services/analyzer/model-cache/` | OCR、转写等模型缓存 | 可重建，但重新下载耗时 |
| `services/analyzer/.venv/` | Python 分析环境 | 可重建，需重新安装依赖 |
| `node_modules/` | Node.js 依赖 | 可通过 `npm ci` 重建 |
| `.wrangler/` | 本地 Cloudflare D1/R2 运行数据 | **不能随便删除** |
| `.next/`、`.vinext/`、`dist/` | 构建缓存和构建结果 | 停止服务后可重建 |
| `outputs/` | 本地打包产物 | 确认不再需要后可删除 |

## 整理原则

1. 根目录配置文件如 `package.json`、`vite.config.ts`、`wrangler.local.jsonc` 必须留在根目录。
2. 不把框架约定目录随意合并，否则构建和运行工具可能无法定位。
3. 不把 `.dev.vars`、Cookie、数据库或模型密钥提交到 Git。
4. 移动启动入口后，必须同步更新 README、界面提示和自动化测试。
5. 清理体积前先备份，优先清理可重建缓存，不动业务数据。
