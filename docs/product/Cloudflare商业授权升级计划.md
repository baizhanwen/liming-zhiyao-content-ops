# 利明智耀本地商业版：Cloudflare 授权与 AI 服务升级计划

## 1. 目标与边界

本计划用于未来把“纯本地商业交付版”升级为“客户数据本地保存、核心智能能力云端授权”的混合架构。客户仍通过本机或局域网地址使用系统，不访问利明智耀的业务后台；客户主机仅在许可证验证、核心知识检索和 AI 生成时主动访问利明智耀 HTTPS API。

云端不接管客户项目管理、成员、原始视频、音频、关键帧、发布记录和历史报告。默认只接收完成任务所需的字幕、OCR、画面描述及有限项目上下文，并在请求完成后丢弃正文。

## 2. 目标架构

```text
客户浏览器 → 客户本地 Web/API → 客户本地 D1/R2/分析器
                                  ↓ HTTPS 443（主动出站）
                         利明智耀 Cloudflare Worker
                         ├─ 许可证与设备验证
                         ├─ 套餐、功能与用量控制
                         ├─ 核心知识检索
                         ├─ 私有 Prompt 组装
                         ├─ DeepSeek 等模型调用
                         └─ 结构化结果校验与返回
```

## 3. Cloudflare 资源

- Workers：公开版本化 API，例如 `https://api.limingzhiyao.com/v1/*`。
- D1：客户、许可证、设备激活、功能权限、用量与审计记录。
- Secrets：模型 API Key、令牌签名私钥、内部服务凭证。
- R2：仅在异步长任务确有需要时保存加密临时材料，并设置自动过期。
- Queues：长视频或模型重试任务异步化；首版可不启用。
- 自有域名与 WAF：限制请求大小、速率、异常来源及重放攻击。

## 4. 数据模型

核心表建议包括：

- `customers`：客户主体、状态、合同编号。
- `licenses`：许可证、有效期、设备上限、离线宽限期。
- `license_features`：视频分析、内容生成、公众号图片等功能授权。
- `device_activations`：随机 installation ID、公钥、首次和最近心跳。
- `usage_records`：功能类型、Token、结果状态、幂等请求号。
- `knowledge_sources` / `knowledge_atoms`：核心方法知识及版本。
- `generation_requests`：只保留必要元数据，不默认保存客户正文。
- `security_audit_logs`：激活、解绑、停用、额度变化与管理员操作。

## 5. API 设计

### 激活与授权

- `POST /v1/licenses/activate`：许可证＋installation ID 换取设备凭证。
- `POST /v1/licenses/verify`：返回有效期、功能、额度和离线宽限期。
- `POST /v1/licenses/refresh`：轮换短期访问令牌。
- `POST /v1/licenses/deactivate`：受控解绑旧设备。

### AI 能力

- `POST /v1/generate/video-report`
- `POST /v1/generate/content`
- `POST /v1/generate/topic-fields`
- `POST /v1/generate/wechat-image-copy`

服务端完成知识检索、Prompt 组装、模型调用和结构校验，只返回最终结果、可追溯知识 ID 与用量，不返回核心知识原文和系统 Prompt。

## 6. 客户端改造

新增 `lib/commercial-service-client.ts`，所有云端请求只能由本地后台发起，浏览器不得直接持有设备令牌。设备凭证优先存入 Windows Credential Manager；本地数据库只保存非敏感授权摘要。

建议使用安装时生成的随机 installation ID 与设备密钥对，而不是强绑定 CPU 或主板序列号。每个请求包含：短期令牌、请求时间、幂等键、正文摘要和签名，服务端限制时间窗口以防重放。

## 7. 隐私与故障策略

- 原始视频、原始音频、图片和完整业务数据库不上传。
- 标准模式发送必要字幕；隐私模式在本地脱敏姓名、电话、金额和客户名。
- 请求完成后正文立即删除，仅保留客户编号、功能、Token、耗时和状态。
- 授权服务短暂不可用时允许 3～7 天宽限；本地查看、导出与非 AI 功能继续可用。
- 到期或停用时只冻结新增 AI 调用，不锁死客户已有数据。

## 8. 分阶段实施

1. 建立许可证、客户和设备后台，完成激活、验证、解绑。
2. 将模型 API Key 和调用代理迁到 Worker，加入额度与幂等控制。
3. 迁移核心知识检索和 Prompt 组装，保留本地兼容适配器。
4. 加入隐私模式、离线宽限、审计、告警和管理后台。
5. 灰度迁移现有纯本地客户；保留明确的版本回退与数据导出能力。

## 9. 上线验收条件

- 复制客户安装目录到第二台设备后不能绕过设备上限。
- 浏览器、日志和本地数据库中不存在模型 Key、签名私钥或完整系统 Prompt。
- 重放、并发和失败重试不会重复扣费。
- 云端故障不会导致客户已有数据不可查看或导出。
- 不同客户之间的许可证、知识调用、用量和日志严格隔离。
- 完成隐私政策、数据处理约定、软件授权协议和应急响应流程。

## 10. 暂不实施的内容

当前阶段先交付纯本地商业版。本计划不在当前版本中部署公网 Worker，不产生 Cloudflare 持续费用，也不改变现有本地模型配置；后续商业客户数量和服务模式稳定后再启动。
