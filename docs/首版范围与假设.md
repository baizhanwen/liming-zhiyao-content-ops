# 首版范围与施工假设

## 当前已冻结范围

本轮先完成阶段 0 和阶段 1 的可继续开发基线：

1. 工作台信息架构与响应式高保真原型。
2. 公司、成员、客户项目、项目成员、邀请、任务与审计日志的数据地基。
3. 服务端组织与项目双重校验规则。
4. D1 结构化数据和 R2 私有媒体的部署声明。
5. 旧系统可复用规则与废弃项审计。

## 暂行假设

- 第一版聚焦抖音，但数据模型保留平台字段，不把业务规则写死在单一平台。
- 首批按 1 家服务公司、5 至 20 个客户项目、50 名以内协作成员设计。
- 默认模型优先 DeepSeek，统一适配层仍必须允许切换 GLM；本轮不写入任何模型密钥。
- Python 分析服务独立部署，Cloudflare 只负责任务创建、鉴权、数据与队列。
- 客户成员可以登录参与审核，项目角色默认为 `client`。
- 第一版采集公开评论样本；客户后台数据采用人工导入，不依赖平台私有接口。
- 身份认证在 Sites 预览环境使用托管身份头；正式公网登录方案进入完整功能开发前确认。

## 本轮不实现

- 真实抖音下载、验证码或自动发布。
- ASR、OCR、关键帧和模型调用。
- 真实成员邀请邮件和公网账号体系。
- 客户数据导入、报告导出和计费。

这些能力需要真实部署位置、模型供应商和登录方案确认后再进入开发，避免形成无法上线的假闭环。
