# 审核、日历与发布契约

更新时间：2026-08-05

## 状态流

内容状态按以下主路径单向推进：

`draft / internal_revision → internal_review → client_review → shooting_ready → shot → editing → publish_ready → published`

- 创作者、策划和项目负责人可以提交内部审核并推进制作状态；
- 内部审核人可以通过到客户审核，或填写原因退回内部修改；
- 客户只能处理客户审核、查看客户可见评论，不能查看内部评论；
- 发布成功必须保存平台和线上作品链接，随后同步内容状态与有效排期；
- 状态更新使用旧状态和当前版本作为乐观锁，避免并发覆盖。

## 版本与审核

`content_reviews` 必须绑定 `content_version_id`。每个内容、审核阶段和轮次唯一；提交新一轮审核时递增轮次。审核决定只作用于提交时的稿件版本，后续人工或 AI 新版本不会篡改旧审核事实。

`content_comments` 同样绑定稿件版本，并区分 `internal` 与 `client` 可见性。评论解决使用独立时间和处理人字段，不删除原评论。

## 日历与发布

`content_schedules` 保存平台、计划时间、时区、状态和备注。同一内容最多保留一条未取消的有效排期，取消后可以重新安排。

`publication_records` 保存每次发布尝试；预约、发布中、成功、失败和取消都保留。发布失败必须填写原因，发布成功必须填写可访问的作品 URL。

## 当前阶段边界

阶段 4 的内部审核、客户审核、版本评论、内容日历、制作状态和发布记录已经接通。自动发布、平台私有接口和运营数据回流不在本阶段；数据导入、指标、图表与报告属于阶段 5。
