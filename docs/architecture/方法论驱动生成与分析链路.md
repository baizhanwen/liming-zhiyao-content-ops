# 方法论驱动生成与分析链路

## 目标

把“方法论”从一段混在事实资料里的长提示词，改成每次任务可选择、可追溯、可验收的方法计划。方法只规定模型如何组织、判断和检查，不提供客户事实，也不能替代视频证据。

## 统一上下文分层

每次模型调用按以下顺序组装上下文：

1. **本次任务**：选题要求、生成目标、分析对象和输出格式。
2. **项目事实**：已确认的品牌知识、项目记忆、业务约束和本企业空间数据。
3. **方法计划**：程序根据任务类型、平台、阶段和风险，从授权方法目录中选择的一组规则。
4. **参考案例**：对标视频、历史文案、灵感卡片等，只能用于学习结构或表达，不自动成为项目事实。
5. **证据与平台约束**：视频分析必须引用 ASR、OCR、关键帧和时间码；发布规则单独作为硬约束。

任何来源只能停留在自己的层级。方法不能生成事实，案例不能证明客户信息，单条视频结论不能自动升级为稳定项目经验。

## 三条业务链路

### 选题中心

`用户输入 → 项目事实 → 选择选题方法计划 → 参考内容 → 生成字段 → 返回方法快照`

方法计划用于确定受众、矛盾、角度、承诺和结构；结果必须能追溯到本次计划及实际项目来源。

### 内容生产

`选题任务 → 项目事实 → 选择内容方法计划 → 对标/历史参考 → 生成口播稿 → 质量验收 → 保存版本与审计`

默认只检索中高置信度的 `method / principle / anti-pattern` 授权原子。每次只加载与当前任务相关的方法，不把整库塞给模型。生成结果必须记录采用的方法计划 ID 和方法 ID。

### 视频分析

`媒体证据 → 内容类型识别 → 选择分析量表 → 分段分析 → 汇总 → 证据校验 → 保存方法元数据`

通用量表检查证据边界、单一核心、开头兑现和口播结构；再按知识口播、卖点、痛点、结果或人设选择专项量表。所有结论仍必须绑定 ASR、OCR、画面或时间码。长视频断点绑定方法签名，方法变化后不会误用旧分段结果。

## 审计与版本

每次调用至少保存：

- 方法目录版本、计划 ID、选中方法 ID；
- 本次任务、项目事实、参考来源的分层清单；
- 输入快照、输出版本和质量验收；
- 视频分析的方法签名和证据来源类型。

这样可以回答“为什么这次模型这样写/这样判断”，也可以在方法升级后识别哪些旧结果需要重新生成。

## 导入方法包的治理

`03_Skill库`、`dbskill` 和 `data` 作为上游参考资产保留，不直接参与应用编译，也不整包注入模型。进入运行时前必须经过：去重、去推广与残句、风险判断、任务适配、人工确认和版本化。现有授权原子只作为补充方法引用，核心链路由受控方法目录路由。
