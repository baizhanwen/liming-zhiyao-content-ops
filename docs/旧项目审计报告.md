# 旧项目只读审计报告

审计对象：`E:\抖音账号视频分析2.0`  
审计日期：2026-08-05  
结论：旧项目适合作为业务规则和样例数据来源，不适合作为新平台的代码地基。

## 可复用资产

- 媒体处理流水线的阶段划分：入库、音频提取、转写、统计、语义洞察、看板。
- 文件哈希缓存、已有转写复用、失败阶段可重跑等幂等思路。
- 结构化大模型输出的 JSON 提取、截断修复、重试和字段校验。
- 钩子原文、术语、结构时长等结论必须回到原文验证的规则。
- 统计口径：高表现阈值使用 `max(P80, 中位数 + 2 × MAD, 100)`；选题分组至少 3 条样本；常见结构至少重复 2 次且覆盖 20%。
- 外置提示词及“学结构、不洗稿”的内容生成原则。
- 原始媒体、转写、统计结果和生成内容分层保存的概念。
- 清理原始媒体时先展示文件数和容量，且保留可复用分析产物。

## 必须重构

- `accounts/<账号名>` 文件夹不是多租户数据模型，无法可靠执行公司和项目隔离。
- 全局 `settings.json` 明文密钥改为托管环境密钥，前端和日志都不得返回完整密钥。
- 单机 Flask 页面、业务编排和分析任务耦合，改为 Web/API、队列和 Python 分析服务分层。
- “同时只能分析一个账号”改为按组织配额控制的异步任务队列。
- 账号名和本地路径不能继续充当实体标识，统一改用不可猜测 ID。
- 本地生成的静态报告改为带来源、采集时间和权限校验的网页报告。
- 删除和缓存清理改为软删除、异步物理清理与审计日志。

## 明确废弃

- 旧页面模板、Tailwind 浏览器脚本和 Flask 路由结构。
- 业务数据直接落在项目源码目录。
- 依赖操作者手工保护密钥和客户资料的交付方式。
- 将累计点赞直接解释为因果结论的展示方式。

## 迁移映射

| 旧资产 | 新平台去向 |
|---|---|
| `accounts/index.json` | `social_accounts` 与 `projects` |
| `index/videos.json` | `videos`、`video_metric_snapshots` |
| `transcripts/*.json` | `video_transcripts`，媒体字节进入 R2 |
| `analysis/knowledge_base.json` | 统计结果、内容策略和可检索知识条目 |
| `analysis/insights.json` | `video_analyses`，保留证据与置信度 |
| `generated/*.md` | `content_items` 与 `content_versions` |
| 流水线内存状态 | `analysis_jobs` 与阶段事件 |
| 本机日志 | 结构化任务日志、模型调用记录和审计日志 |

## 首轮迁移约束

旧目录保持只读。迁移工具后续应按“读取、校验、转换、写入、核对数量”的方式单独实现，不在旧目录原地升级，也不复制旧密钥。
